# Docs Sync (CHIMERA)

## Три сорта

- **Генерируемые** — `Docs/Диаграммы/`, карты мира и кадры. Руками не править; числа оттуда.
- **Живые** — `GDD`, `CONSTRUCTOR_GUIDE`, `СТАТУС`, `Паспорта`, `УСТРОЙСТВО_ТЕЛА`. Ведутся руками,
  обновляются при смене этапа.
- **Спеки** — `Docs/superpowers/specs/`. Снимок на дату; не переписывать задним числом, искать преемника.

## Чеклист

- [ ] `Docs/СТАТУС.md` — точка входа: дата сверки, §1 «где мы», §3 «что сделано», §5 «что дальше»,
      §7 «решено». Если разошёлся с генерируемым отчётом — прав отчёт.
- [ ] `Docs/УКАЗАТЕЛЬ.md` — аннотированный каталог; аннотации сняты с текста, не с имени файла.
      Число записей не хардкодить: каталог живой.
- [ ] `GDD` — резолвнутое не переоткрывать; новые решения — только новым разделом/спекой.
- [ ] Новый вид/орган/способность/химера — через `CONSTRUCTOR_GUIDE` (рецепты, тюнинг-карта),
      проверить `BodySlots`/`ValidateSockets`.
- [ ] Крупное — спека в `specs/`, план в `plans/` если строительная; шапки отмен двусторонние.
- [ ] `python Docs/tools/spec_status.py` — ЧИСТО (или объяснённый долг).

## Правила

- **Правило живёт в одном месте, остальные ссылаются.** Не пересказывать `CONSTRUCTOR_GUIDE`/`CLAUDE`
  в трёх документах: пересказы расходятся молча.
- **Что можно проверить машиной — не писать словами, а измерять.** Числа тестов, габаритов, документов
  брать из прогона/детектора, не из памяти.
- `docs-keeper` ловит дрейф терминов и правит доки, а не детектор.
