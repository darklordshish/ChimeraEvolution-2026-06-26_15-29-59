## 2. Пространство, оси, единицы, origin

| параметр | значение |
|---|---|
| единицы | **метры**, 1 unit = 1 m, масштаб объекта **1.0** |
| `+X` | вправо при взгляде вдоль потока (от забора к сбросу) |
| `+Y` | вверх; у лотка `Y=0` — **верх кромки борта** |
| `+Z` | вдоль потока, от забора к сбросу |
| origin | у каждого модуля свой, см. таблицу §3; общий origin файла — `(0,0,0)` |
| форма | без мировых координат и без `SampleGround`; посадка/поворот/высота — Unity |

**Импорт (проверено в Unity 6000.4.7f1).** FBX собран с `Apply Scale = All` и `Bake Space Transform = on`, поэтому в Unity все узлы **identity** (`Lcl Translation = 0`, `Lcl Rotation = 0`, `Lcl Scaling = 1`), а меш — в метрах. Настройки импорта, при которых числа паспорта сходятся:

- `Global Scale = 1`
- `Convert Units = off` (`useFileUnits = false`), `Use File Scale = off`
- `Bake Axis Conversion = off`
- `Normals = Calculate`, `Smoothing Angle = 0` (плоские грани)
- `Material Import = None` (материалы — отдельные ассеты, назначает интегратор)
- `Generate Colliders = off`

**Проверка осей по импорту.** `AW_Trough_12m` в Unity занимает `X −2.1…2.1`, `Y −1.8…0`, `Z 0…12` — то есть `+Z` идёт вдоль потока, `+Y` вверх, `+X` вправо. `AW_WaterFall` — `Y −4.4…0`; `AW_Dam` — `Y 0…6.2`.

## 5. Опоры и швы

### 5.1. Бык

- шаг **12 м** (в пределах 12–20 м);
- `AW_PierBase` — 2.4 × 0.6 × 1.8, база шире ствола на 0.6 м по X и Z;
- `AW_PierShaft` — 1.8 × 4.0 × 1.2 внизу, 1.4 × 0.8 вверху, сужение 1:10; **высота меняется только масштабом локального Y** (0.25–1.75 → 1–7 м), сечение X/Z не трогать;
- `AW_PierCap` — 2.0 × 0.35 × 1.4, свес 0.3 м на сторону;
- полная высота по умолчанию: **0.6 + 4.0 + 0.35 = 4.95 м**; при этом кромка лотка выше земли на **6.75 м** (низ тела `−1.80`).
- **Стек постановки:** база `Y = ground`; ствол `Y = ground + 0.6`; капитель `Y = ground + 0.6 + shaft_height`; кромка лотка `Y = ground + 0.6 + shaft_height + 0.35 + 1.80`.

| тип | высота ствола | кромка над землёй | низ тела над землёй |
|---|---:|---:|---:|
| низкий (AW-R/AW-L) | 1.6 м (scale 0.4) | 4.35 м | 2.55 м |
| средний (AW-F) | 2.0 м (scale 0.5) | 4.75 м | 2.95 м |
| высокий (AW-RS) | 4.0 м (scale 1.0) | 6.75 м | 4.95 м |

### 5.2. Шов

- ставится **каждые 24 м** (через две 12-метровые секции);
- зазор между пилястрами **0.12 м**, пилястра **0.25 м**, выступ **0.12 м**;
- шов читается на борту и **под телом**; вода непрерывна — шов не проходит сквозь воду;
- `AW_Seam` (264 тр) — LOD0; `AW_Seam_LOD1` (72 тр) — для дальности.

## 6. Четыре типа: сборка из кита

Тип выбирается **по воде на сиде**, а не по близости станции. Нет воды — `absent` (объект не ставится), не «пустой акведук».

### 6.1. AW-R — река

| параметр | значение |
|---|---|
| длина | 24–48 м (2–4 секции) |
| опоры | 3–5 быков, шаг 12 м, ствол 1.6–3.0 м |
| лоток | 3.0 м внутр., вода −0.30 м от кромки |
| забор | `AW_Intake` на старте |
| сброс | `AW_SpillLip` в конце + `AW_WaterSideSpout` вбок; при простом пересечении сброса может не быть |
| вода | `AW_WaterTrough_12m` на каждую секцию, `AW_WaterSpill` на губу, `AW_WaterSideSpout` на боковой выпуск |
| нос быка | `AW_PierNose` на upstream-грань каждого быка (`z = z_быка − 0.9`) |

Сборка: 2 секции → 3 быка; 4 секции → 5 быков. Быки ставятся в русле/на берегах, река остаётся открытой.

### 6.2. AW-L — озеро

| параметр | значение |
|---|---|
| длина | 72–144 м (6–12 секций) |
| опоры | 4–6 на 50 м, шаг 10–15 м, ствол 1.6–2.2 м |
| лоток | 3.0 м внутр., вода −0.30 м от кромки |
| забор | `AW_Intake` у берега |
| сброс | `AW_SpillLip` с возвратом в озеро или без сброса |
| берег | `AW_AbutmentPlinth` + `AW_AbutmentShaft` на обоих концах |

Сборка: 6–12 секций, быки каждые 12 м (шаг можно уменьшить до 10 м, ставя бык под каждую секцию); линия повторяет берег 2–3 изломами по 3–8°.

### 6.3. AW-RS — водохранилище

| параметр | значение |
|---|---|
| длина | 60–120 м (5–10 секций) |
| опоры | 3–4 высоких быка, ствол 4.0 м (scale 1.0), кромка 6.75 м |
| лоток | 3.0 м внутр., вода −0.30 м от кромки |
| плотина | `AW_Dam` (10 × 6.2 × 3.0) в начале |
| затвор | `AW_GateTower` на гребне плотины (`Y = 6.2`), `AW_Gate` на upstream-грани (`z = −1.65`) |
| сброс | `AW_SpillLip` + 2–3 `AW_SpillStep` + `AW_WaterFall` + `AW_WaterPlunge` + `AW_Foam` + `AW_Apron` |
| вода | вода лотка + вода губы + полотно; **водохранилище — вода мира, не акведука** |

Сборка: плотина в `z = 0`; первая секция лотка в `z = 3.0` (за плотиной); быки в `z = 3, 15, 27, 39`; сброс в конце. Ступени перелива ставятся под губой: первая — на **1.0–1.5 м ниже кромки**, каждая следующая — на **0.8 м ниже** и **0.3–0.5 м дальше по Z**; 2–3 ступени, ширина 2.2 м. Для AW-RS лоток можно расширить масштабом X **1.07–1.40** (внутренняя 3.2–4.2 м); воду масштабировать тем же X; быки/швы не трогать.

### 6.4. AW-F — водопад/сброс

| параметр | значение |
|---|---|
| длина | 36–60 м (3–5 секций) |
| опоры | 3–4 быка, шаг 12 м, ствол 2.0 м (scale 0.5) |
| лоток | 3.0 м внутр., вода −0.30 м от кромки |
| забор | `AW_Intake` на старте |
| сброс | `AW_SpillLip` + `AW_WaterSpill` + `AW_WaterFall` (4.4 м) + `AW_WaterPlunge` + `AW_Foam` + `AW_Apron` |
| масштаб падения | `AW_WaterFall` масштабируется по локальному Y **0.36–1.36** → 1.6–6.0 м |

Сборка: 3 секции (36 м), 4 быка; последние 2 быка можно опустить на 0.8–1.5 м, но тогда лоток должен получить уклон/ступени — в ките ступеней лотка нет, поэтому по умолчанию лоток горизонтален, а перепад даёт губа.

### 6.5. Общая формула постановки

```
z = 0, 12, 24, …            — секции лотка
z = 12, 24, …               — швы (через 24 м)
z = 0, 12, 24, …            — быки (база/ствол/капитель)
z = 0                       — оголовок забора (на первой секции)
z = last + 12               — губа сброса (на конце последней секции)
z = last + 12.9             — полотно водопада (origin по воде)
z = last + 13.5             — приёмный плёс / пена / апрон
x = ±2.25 / ±1.8            — лестница / перила на кромке
```

Высоты: `rim = ground + 0.6 + shaft_height + 0.35 + 1.80`; вода в лотке `rim − 0.30`; вода на губе `rim − 0.30`; верх полотна `rim − 0.30`; плёс — уровень приёмной воды (ставит интегратор).

## 8. LOD и коллайдер

- **LOD0:** все объекты без суффикса `_LOD1`.
- **LOD1:** `AW_Trough_12m_LOD1` (28), `AW_Seam_LOD1` (72), `AW_PierBase_LOD1` (12), `AW_PierShaft_LOD1` (12), `AW_PierCap_LOD1` (12), `AW_AbutmentPlinth_LOD1` (12), `AW_AbutmentShaft_LOD1` (12), `AW_Intake_LOD1` (36), `AW_SpillLip_LOD1` (36), `AW_SpillStep_LOD1` (12), `AW_Apron_LOD1` (12), `AW_Dam_LOD1` (36), `AW_GateTower_LOD1` (24).
- LOD1 — тот же силуэт и габарит, без фасок/пилястр/решётки; **вода и пена LOD не имеют** — на дальности выключаются.
- **Коллайдер — один меш `AW_Collider`** (оболочка лотка, 28 тр): верх бортов и внешние стенки — ходовая часть; внутренняя полость открыта. В Unity: `MeshCollider` с `convex = false`, рендерер выключить.
- **Без коллайдера:** вода, пена, мох, мокрый пояс, решётка, лестница, перила, затвор. Это не ходовая часть.
- **Опоры:** если нужен коллайдер быка, источник — `AW_PierBase_LOD1` / `AW_PierShaft_LOD1` / `AW_PierCap_LOD1`; это **не** ходовая часть и в `AW_Collider` не входит.
- Один `MeshCollider` на собранный экземпляр: интегратор либо ставит `AW_Collider` на каждую секцию, либо собирает общий меш; вода/пена в него не попадают.

## 11. Что не делалось и известные ограничения

- Нет префабов, сцены, `LODGroup`, `MeshCollider`, NavMesh, камер A1–A4, 20-сидовой матрицы и тестов — это интеграция.
- Это **low-poly blockout**, не финальный арт: фасетка, 2 тона на семейство, без текстур и декоративной мелочи.
- Шов — накладные пилястры + полоса под телом; сквозного зазора в теле нет (вода непрерывна).
- Уклон лотка и ступени лотка не заложены: по умолчанию лоток горизонтален, перепад даёт губа/водопад. Если нужен наклонный лоток — это отдельная правка формы (секция с уклоном), а не масштаб.
- `AW_WaterFall` — объём 0.6 м; при масштабе Y меняется высота, толщина и ширина остаются.
- Мох — на одной (теневой) стороне секции; при повороте модуля сторона выбирается интегратором.
- Бюджет: кит 2 100 тр; сборка ~100 м — ориентировочно 3.5–4.0 тыс. тр LOD0 (в пределах арт-брифа 2.5–5 тыс./100 м). Точный замер — после интеграции, `G8`.
