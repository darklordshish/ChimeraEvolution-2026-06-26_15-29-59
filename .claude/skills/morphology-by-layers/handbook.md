# Морфология по слоям — инструкции

Разбор того, что в `SKILL.md` сказано коротко. Читать, когда собираешься работать руками, а не когда
вспоминаешь правило.

Полное обоснование методики: `Docs/superpowers/specs/2026-08-21-metodika-morfologii.md`.
Мастерская и раскладка папок: `Anatomy/README.md`.

---

## 0. Python на этой машине

Голый `python` — сломанная заглушка WindowsApps (печатает «Python», код возврата 49), лаунчера `py`
нет. Рабочий интерпретатор один:

```bash
/c/ProgramData/Anaconda3/python.exe
```

Русский вывод требует `PYTHONIOENCODING=utf-8`.

**Осторожно с heredoc:** backslash-эскейпы (`\n`) по пути в оболочку схлопываются и ломают код.
Для перевода строки внутри патч-скриптов писать `chr(10)`, а не `'\n'`.

## 1. Начать слой

Слои принимаются по одному: кости → мышцы → покровы. Переключается срез — полем вида:

```csharp
SpeciesSO.buildLayers = 1   // только кости
                      = 2   // + мышцы
                      = 3   // + признаки (уши, мочка, надбровье)
                      = 4   // всё, включая вычитание (рот, ноздри)
```

Поле лежит в ассете вида (`Assets/_Chimera/Data/<Вид>.asset`), меняется в инспекторе Unity. Приёмка
слоя — **скрин из Unity**, а не мой рендер: рендер проверяет меня, игру проверяет пользователь.

## 2. Снять эталон с референса

Единственный законный источник пропорций — изображение, а не таблица промеров.

### 2.1 Положить сетку

```bash
PYTHONIOENCODING=utf-8 /c/ProgramData/Anaconda3/python.exe Anatomy/tools/grid.py \
  Anatomy/species/wolf/ref/photo/wolf_standing_1.jpg --step 100 \
  --out Anatomy/species/wolf/out/photo_grid.png
```

Без сетки чтение координат с картинки — то же гадание, только с референсом в руках.

### 2.2 Выбрать опоры

Три числа задают всю меру снимка: **линия земли**, **высота холки** (или темени у двуногого) и
**горизонтальная привязка** (обычно нос либо холка). Дальше пиксель переводится в метры одной
формулой.

### 2.3 Записать в файл вида

`Anatomy/species/<вид>/etalon/body.py` — точки хранятся **в пикселях исходника**, а не в метрах.
Так их может перепроверить кто угодно, наложив ту же сетку. Пример — эталон волка, там же расписано,
что именно эти точки говорят в долях холки.

Детектор подхватывает эталон сам, если файл на месте.

### 2.4 Проверить себя

Снятый эталон обязан отвечать на вопрос «а не выдумал ли я его». Признак выдумки — контур, который
нельзя показать пальцем на фотографии. Реальный случай: собранный из краниометрии эталон вёл линию
верха от холки **вниз** к носу, тогда как у волка в стойке затылок стоит на 1.20 высоты в холке, то
есть **выше спины**. Модель сошлась с выдумкой на 2.1 см и всё равно читалась неправильно.

## 3. Гонять детектор

```bash
# всё тело, все слои, сравнение с эталоном
python Anatomy/tools/render.py --species wolf

# одна часть в СВОЁМ масштабе (у головы свой порог)
python Anatomy/tools/render.py --species wolf --part голова

# срез слоёв — как buildLayers в игре
python Anatomy/tools/render.py --species wolf --part голова --layer 1
```

Картинки ложатся в `Anatomy/species/<вид>/out/`, папка производная и в git не идёт.

### Что означают числа

```
РАСХОЖДЕНИЕ С ЭТАЛОНОМ: верх 0.029 ср / 0.107 макс   низ 0.063 ср / 0.159 макс
   круп           верх -0.036   низ -0.093
   ...
```

- **ср / макс** — метры. Ориентир: при холке 1.17 расхождение 0.03 это 2.5%.
- **знак**: минус = наш силуэт **ниже** эталона, плюс = выше.
- разбор по областям нужен потому, что одно число говорит «плохо», а карта — «где именно».

### Чего детектор не умеет

- **Не заменяет глаз.** Он меряет то, что ему задали мерить. Смотреть картинку обязательно.
- **Не знает про части без эталона** — честно пишет «сравнивать не с чем».
- **Он должен считать ИГРОВОЕ поле.** Правишь `BoneMesher.cs` — сверяй детектор в тот же заход.
  Он уже дважды расходился с игрой: коэффициент реза и оси сечения.

## 4. Раздать работу парам агентов

Одна пара на часть: **скульптор** строит, **критик** меряет. Бриф по шаблону из `SKILL.md`.

Что делает бриф рабочим:

- **пути к файлам референсов**, а не описания — агент должен посмотреть картинку сам;
- **замороженные суставы** названы поимённо: череп задаёт посадку глаз, шея — посадку черепа;
- **команда детектора** целиком, чтобы агент не выдумывал свою проверку;
- **требование вернуть фрагмент**, а не переписать общий файл.

Агент стартует холодным и заново выводит контекст, поэтому бриф — одна часть, один слой, всё нужное
внутри.

---

## 5. Принять работу пары

| Проверка | Как |
|---|---|
| замер приложен? | нет прогона детектора — работа не читается |
| суставы на границе не поехали? | сверить с брифом поимённо |
| фрагмент, а не общий файл? | иначе правки соседей затрутся молча |
| целое собирается? | мержит и строит **только ревизор**, стыки видны лишь на целом |

Дальше ревизор пишет в `<вид>.py` → блок `bones` в `SpeciesBootstrap.cs` → просит пользователя
прогнать **«Chimera → Создать дефолтные виды»** и сохранить сцену.

**Гейт бутстрапа:** пользователь про этот пункт забывает, а без него в `.asset` остаются старые
кости, и плейтест показывает прежнего зверя. Признак — «ничего не изменилось» при чистых числах.

## 6. Ошибки, которые уже стоили итераций

| Симптом | Настоящая причина |
|---|---|
| «Двадцать проверок ok», а на экране плохо | метрика мерит лишь то, что догадались померить |
| Расхождение упало вдвое, зверь читается хуже | эталон выдуман и, возможно, перевёрнут |
| Часть тела «оторвана» | мерили габариты мест, а не реальные границы деталей |
| Деталь висит «с лагом в один» | `Object.Destroy` отложен до конца кадра; сносить все одноимённые |
| Голова уехала вперёд вместо вверх | у места молча переключилась длинная ось (запас < 5%) |
| Часть морды строится не там, где считают данные | дубль имени кости — вторая заняла место первой |
| Морда осталась конусом после десятка правок | конструкции нет: одна кость плюс объёмы сверху |
| Уши/ухо повёрнуты не так, как в игре | детектор считал сечение в своих осях, а не игровых |

## 7. Что лежит в мастерской

```
Anatomy/
  tools/skel.py      модель кости: позиции и повороты РОВНО как в Unity (Euler ZXY, рост по +Y)
  tools/render.py    детектор: то же поле, что BoneMesher; --part, --layer, сравнение с эталоном
  tools/grid.py      координатная сетка на референс
  species/<вид>/
    <вид>.py         данные вида: анатомические точки → кости → вывод для C#
    ref/             референсы: photo, skeleton, muscle, scheme, _other (отвергнутое с причиной)
    etalon/          контуры, снятые с натуры
    out/             рендеры (производное, в git не идёт)
```

Раскладка одинаковая для любого вида — новый заводится теми же папками.
