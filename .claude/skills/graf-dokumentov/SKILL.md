# Граф документов: держать доки и память связными

Документы и память — одна база знаний. Точность того, что сессия достаёт из неё, держится не хранилищем, а
**свежестью и непротиворечивостью** (ресёрч `Docs/reports/Многослойная память агентов.md`): ссылка на переименованный
файл молчит, запись памяти пересказывает отменённое правило, спека без входящих ссылок забыта. Граф строит детектор
`Docs/tools/doc_graph.py` из самих markdown-ссылок; отдельной базы нет, источник правды — файлы в git.

Узлы: `.md` в git (кроме `Experiments/` и служебных папок) и файлы памяти. Рёбра: `[текст](путь)`, пути `.md` в
обратных кавычках, `[[имя]]` в памяти.

## Когда

- спека принята, выполнена или отменена (spec-first: после каждой) — **обязательно**;
- поставка линии с письмом, новое письмо `FEEDBACK-*`/`ZADACHA-*`;
- правило поменялось в CLAUDE.md, CONSTRUCTOR_GUIDE.md, СТАТУС.md или скилле;
- перед коммитом, задевающим `Docs/`, `Референсы/`, `.claude/skills/`.

## Порядок (5–10 минут)

1. **Детекторы:**
   ```bash
   python Docs/tools/spec_status.py
   python Docs/tools/doc_graph.py --all
   ```
   Битые ссылки — красное, гейт их не пропустит: чинить путь к настоящему файлу. Ссылка на файл, которого в main нет
   (черновик линии), — перенести файл в main или убрать ссылку в текст `путь` (не исключение в детекторе).
2. **Связать новое.** Новая или изменённая спека должна быть:
   - в `Docs/УКАЗАТЕЛЬ.md` (это проверяет `spec_status.py`);
   - со ссылками на родителей в шапке («Родители», «Отменяет») — и родитель знает о ней (отмена двусторонняя);
   - упомянута там, где по ней работают: `СТАТУС.md` (если меняет этап), CONSTRUCTOR_GUIDE.md (если меняет правило),
     паспорт витрины (если меняет форму).
3. **Сироты.** В списке `--all` найти документы, которых коснулась работа; если важный документ сирота — сослаться на
   него оттуда, где его будут искать (СТАТУС, УКАЗАТЕЛЬ, спека-родитель). Старые сироты не чинить пачкой без повода.
4. **Память.** Предупреждение «память ссылается на отменённое» — открыть запись: если она пересказывает отменённое как
   действующее, поправить запись тем же заходом (ссылка на новый источник). Если поменялось правило, у которого есть
   запись памяти, — запись ссылается на новый документ, а не пересказывает его. Правила ведения — запись
   `chimera-pamyat-pravila`. Индекс `MEMORY.md` — строка до ~150 знаков, раздел по `scope`.
5. **Обратные ссылки:** `python Docs/tools/doc_graph.py --write` → `Docs/Диаграммы/ССЫЛКИ.md`, закоммитить вместе с
   правкой документов.
6. **Итог в одну строку** в ответе: битых 0, сирот N (из них новых k), предупреждений памяти m.

## Чего не делать

- Не заводить список исключений в детекторе ради «шумной» ссылки — чинить ссылку (CLAUDE.md: список исключений —
  признак неверной структуры). Исключения сейчас только по смыслу: `Experiments/` не вливается в main по ЗОНЫ.md.
- Не править тело принятой спеки ради ссылок, кроме битого пути (правило «одна линия партии»: меняется шапка).
- Не переносить архив переписки (`Docs/models/archive/`) ради сирот: архив и должен быть без входящих.

## Где что

- `Docs/tools/doc_graph.py` — детектор графа; в гейте (`Tools/git-hooks/gate-main.sh`, шаг 1в) останавливает битые ссылки.
- `Docs/tools/spec_status.py` — статусы спек, отмена, указатель.
- `Docs/Диаграммы/ССЫЛКИ.md` — обратные ссылки, генерируется.
- Память: свой git в папке памяти, хук Stop коммитит её сам (`.claude/settings.json`); откат — `git log` там.
