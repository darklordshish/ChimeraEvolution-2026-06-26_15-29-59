# Глобальный слой: как хранить объёмы и как отображать тело в тело

Ресёрч 07.10.2026 к спеке глобального слоя (решения — спека двух слоёв `2026-09-27-smeshenie-siluetnogo-grafa.md` §4–§6;
здесь не переоткрываются). Два вопроса геймдизайнера: (1) как в индустрии хранят «мышечные» объёмы, чтобы смешивать
существа, и чем плох каждый способ; (2) математика отображения «тело шасси → тело по идентичности»: не меньше пяти
подходов, выбор по вычислительной цене.

## 1. Индустрия: как хранят объёмы

| школа | пример | как устроено | чем платят |
|---|---|---|---|
| **Общий шаблон семейства + числа** | SMAL (2017): одна модель на четвероногих от кошки до бегемота; SMPL у людей; MetaHuman и Character Creator — ползунки тела на общей сетке | шаблон с одной топологией; вид — точка в пространстве параметров (PCA или ручки); смешение видов — линейно по параметрам | каждый вид надо «зарегистрировать» на шаблон; то, что в шаблон не влезает (змея, иглы), — вне модели |
| **Перенос шаблонной анатомии на свою кожу** | Anatomy Transfer (SIGGRAPH Asia 2013); Ziva VFX 1.6 (Meg и др.) | эталонные кости и мышцы деформируются под кожу нового персонажа (гармоническая деформация, «варп костей + варп пространства») | тот же шаблон, только сразу с мышцами; у Ziva — условие «похожая топология» |
| **Неявная кожа вокруг скелета, у каждого своя** | Spore: метабол на каждую точку позвоночника + marching cubes | тело строится из скелета заново, смешивать не нужно — каждый собран сам | топологически надёжно, но «мягко»; соответствия объёмов нет — морф двух тел даёт двоение |

**Вывод.** Никто не смешивает существа без соответствия. Его заводят на уровне шаблона семейства: SMAL прямо показывает,
что четвероногим хватает одного шаблона, а вид — это числа. У нас соответствие скелетов уже есть (разметка цепей, §4.1
спеки двух слоёв). Для объёмов тот же приём — **общий набор мышечных групп на план тела**: двуногие, четвероногие; змея —
своё семейство. Это и есть «мышцы задаются правилами» (геймдизайнер 02.10). Свободные бугры по виду остаются только для
черт (§5 спеки двух слоёв): они растут из нуля по ступени, а не перетекают.

## 2. Математика: отображение тела в тело

Наше тело — граф узлов (длины, радиусы, сечения, повороты) + поле, по которому раз за разом строится оболочка. Самое
дорогое уже сейчас — изоповерхность: 2–6 мс на подмену, 50–350 мс фоном (замер 29.09). Отображение должно быть дешевле
неё и не ломать тождество «чистый вид = как сейчас».

| # | подход | что нужно | цена | годится нам |
|---|---|---|---|---|
| 1 | **Интерполяция параметров общего шаблона** (бленд-шейпы, PCA SMAL; у нас — `ln` длин и радиусов, повороты по SO(3), §4.3) | соответствие узлов по шаблону | O(узлов) ≈ сотни операций | **да — основной путь**; точное тождество при g = 0 и 1 |
| 2 | **Варп пространства по ориентирам** (RBF, тонкая пластина; ориентиры — наши метки суставов) | пары ориентиров | решение k×k раз на пару (k ≈ 20), затем O(N·k) на точку | для переноса жёстких деталей и блоков; объёмы тянет «резиной», руки у корпуса затягивает в туловище |
| 3 | **Каркас (cage): MVC, гармонические, Green-координаты** | каркас на каждый вид, с соответствием | O(N·C) на точку, координаты считаются заранее | для мешей деталей; каркас — тот же шаблон, только грубее |
| 4 | **Смешение полей** (линейная смесь неявных функций, затем изоповерхность) | ничего: топология любая | два поля вместо одного: цена изоповерхности ×≈2 | запасной путь, где соответствия нет; без выравнивания скелетов даёт двоение конечностей |
| 5 | **ARAP-интерполяция / перенос деформаций** (Alexa 2000; Sumner–Popović 2004) | меши с соответствием | разреженная система: факторизация раз, затем обратная подстановка O(N) | нет: у нас нет постоянной сетки — оболочка каждый раз новая |
| 6 | **Оптимальный транспорт** (барицентры Вассерштейна, свёрточный OT, Solomon 2015) | ничего | итерации Синкхорна по сетке, секунды | только офлайн; массы «расплываются» |
| 7 | **Функциональные карты / поиск соответствия** | ничего, ищет соответствие сам | офлайн, тяжело | не нужно: соответствие у нас задано метками |

**Выбор по цене: подход 1.** При общем шаблоне отображение — смешение чисел узлов: сотни операций против миллионов в
изоповерхности, то есть даром. Дальше та же сборка поля, что и сейчас: ни новой стоимости, ни нового кэша. Остальные
подходы — инструменты для частей, где шаблона нет: 2 — перенос жёстких деталей (уже делаем кадрами костей), 4 —
запасной для целей вне семейства.

## 3. Что это значит для наших пар

- **Пара одного плана** (волк ↔ лось ↔ ёж): парное тело — это просто числа цели в шаблоне шасси. Офлайн-перенос не
  нужен.
- **Пара разных планов** (человек ↔ волк, а это оборотень): шаблоны двух планов разные, но групп конечное число.
  Значит, нужна **таблица соответствия групп «двуногий ↔ четвероногий»** (дельта ↔ мышца плеча зверя, ягодица ↔ круп
  и т. п.). Это конечная таблица, а не общая задача — ровно то, что советовал консилиум формы. Стойка за шасси (решение 8):
  переносятся пропорции и массы, а не постановка ног.
- **Змея** — своё семейство: цель «змея» по-прежнему через варана (решение 12), а запасной путь — подход 4.
