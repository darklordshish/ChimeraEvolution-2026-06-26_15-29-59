# CHIMERA — Эволюция NPC (стохастическая химеризация)

- **Дата:** 2026-07-31
- **Статус:** спека слайса (implementation-oriented). Первая фича ПОСЛЕ под-системы #4b (тело=данные + диспатч психики по составу). Роадмап: **эта → морфология → #4b-4 боссовость**.
- **Родилось из:** брейншторма 2026-07-30. Дизайн собран и одобрен пользователем. См. [[chimera-evolyuciya-npc]] (память), `2026-07-30-4b3-vidovye-moduli-uznavanie-po-sostavu.md`.

## 0. Контекст: payoff платформы

Под-система #4b дала: тело-данные, пул+родство-убийце (уже в `CreatureBody`), диспатч психики по доминанте, узнавание по составу, тинт-по-составу (с развязкой Telegraph). **Эта фича замыкает всё в живую петлю:** NPC убивают друг друга → получают родство к виду жертвы → стохастически надевают её органы → состав едет → доминанта переваливает → психика/узнавание/цвет меняются. Лес начинает эволюционировать сам. Витрина — стелс-лось-дредноут (змеиный камуфляж + волчья пасть + пит-термосенс на лосином танке).

## 1. Scope

Стохастическая химеризация всех NPC-видов на убийство. **4 куска** (инфра ~80% готова — из игрока НИЧЕГО не тащим, база `CreatureBody` едина):
1. **`donors=все` + стартовое родство** — родство ЕДИНАЯ ось (доступность/скидка/шанс), без `AddDonor`/исключений;
2. **грант органа** на убийство (шанс `Install` = родство к виду жертвы; орган уже в вариантах);
3. **ре-диспатч психики** при сдвиге доминанты (гистерезис Medium);
4. **tint NPC** (цвет по составу).

Динамику **высокую** пока (увидеть эффект), баланс вероятности — потом.

## 2. Дизайн

### 2.1 Родство — единая ось; грант органа на убийство
**ЗАДУМКА (пользователь, уточнено):** «открытость ветки» — НЕ отдельная механика, а **производная от родства** (родство к виду > 0 → ветка доступна). Родство уже управляет скидкой цены (`EffectiveCost`); добавляем к нему «шанс гранта» и «видимость в конструкторе». Одна ось вместо `AddDonor`/исключений. `donors=все` у ВСЕХ тел со старта (§2.2) — как игрок; убийство лишь поднимает родство (уже есть в `CreditKiller`).

Грант в `CreatureBody.CreditKiller` (после начисления родства убийце), вынесен в модуль (§2.5):
- **шанс** = родство убийцы к виду жертвы (`killer.GetAffinity(видЖертвы)`), нормированное в вероятность (высокая динамика: напр. `affinity/100`, тюним);
- **что даём:** случайный НАДЕТЫЙ звериный орган жертвы (`this.slots` где `sl.Installed` → вид+орган); `donors=все` → он УЖЕ в вариантах слота убийцы;
- **куда:** `killer.Install(слот, вариант)` — влезет по пулу (`CanInstall` уже гейтит; скидка от родства делает «изученные» виды дешевле) → надел, не влезет → нет («не влезет — значит не влезет»);
- **все виды:** родство даётся ВСЕМ убийцам (гейт `eatsMeat` — только на сытости-регене, не на родстве) → **лось, затоптавший волка рогами, нарастит волчий орган** — единый триггер, лосю отдельного механизма не надо.

### 2.2 `donors=все` со старта + стартовое родство
Все тела (NPC как игрок) получают **`donors`=все виды** при спавне/`Awake` → `BuildSlots` один раз строит слоты со всеми вариантами (родные надеты по умолчанию → чистый вид). **Нет `AddDonor`, нет рантайм-пересборки, нет сброса состава** — главная гоча испарилась вместе с механикой открытия.

**Стартовое родство** — поле `startAffinity` (тумблер отладка↔демка): тело инициализирует родство ко всем НЕ-своим видам = `startAffinity`.
- `startAffinity = 1` (ОТЛАДКА сейчас): все ветки приоткрыты, эволюция видна сразу (низкая скидка, ненулевой шанс гранта);
- `startAffinity = 0` (демка/релиз): ветки закрыты, первое убийство поднимает родство 0→1 = «мягкое открытие» вида; тут же можно вешать UI-тост «изучен вид X» на переход 0→>0.

**Источник «всех видов»** — реестр `SpeciesSO` (бутстрап/папка Data); нужен рантайм-доступ (Resources / сериализованный список) — уточнить в плане.

### 2.3 Ре-диспатч психики (гистерезис Medium)
Доминанта (`MostKin`) сдвинулась → перевесить психику через `PsycheDispatch`.
- **Тело трекает текущую доминанту**; в `Recompute` (после смены состава) сравнивает с прошлой. Сменилась И новая дотянула **Medium** (гистерезис — не дёргаться на границе 50/50) → эмитит `onDominantChanged` (UnityEvent).
- **Слушатель** (тонкий компонент на NPC, напр. `Metamorph`) снимает старую психику (`Destroy`) и вешает новую (`PsycheDispatch.Attach`). Тело про психики НЕ знает — только «моя доминанта сменилась» (слой цел).
- Смена психики = **метаморфоза**: сбрасывает состояние (стаю/цели/мораль) — резко, но это перерождение.
- **ШАССИ НЕ МЕНЯЕТСЯ** (физ. якорь). Расхождение шасси↔доминанта — ФИЧА (волк-шасси с доминантой-Ёж = ёж по поведению/узнаванию; `Regard` уже по `MostKin`, #4b-3).

### 2.4 tint NPC
Включить `tintComposition` эволюционирующим NPC → тело красится смесью состава (`CompositionTint`, уже есть). Развязка `Telegraph.Rebase` (#4b-2) сделана → тинт и телеграф не дерутся. Гейт: включать только эволюционирующим (обычный чистый NPC может остаться на запечённом материале, или тоже тинтить — решить; вероятно всем NPC на платформе, для единообразия).

### 2.5 Модуль (partial `CreatureBody.Evolution.cs`)
Механику §2.1 (грант органа) вынести отдельным partial-файлом (как швы рефактора #1) — отдельный концерн, `CreditKiller` зовёт. В общей базе, доступно любому телу. Трекинг доминанты §2.3 — тоже сюда или в ядро (рядом с `Recompute`). (`donors=все`+`startAffinity` из §2.2 — при спавне/`Awake`, не в этом модуле.)

## 3. НЕ в этом слайсе
- **Морфология** (видеть запчасти) — следующая фича, [[chimera-morfologiya]].
- **Боссовость** — #4b-4, на готовом.
- **Баланс вероятности** химеризации (сейчас высокая, чтобы видеть) — тюнинг потом.
- **Градуированное открытие органов по родству** (идея пользователя, на баланс): вместо «родство>0 → вся ветка», открывать органы вида по ПОРОГАМ родства (слабые рано, сильные позже) — тонкий геймплей-проход, когда будем балансить.
- **Рудиментарные хвосты** (chassisOnly-слот под змеиный хвост) — backlog данных видов, рядом, но не тут.
- **Обратный тинт/деэволюция** — не рассматриваем (органы только копятся до пула).

## 4. Точки касания

- `Player/CreatureBody.cs` — `CreditKiller` зовёт грант; `Recompute` трекает доминанту + эмитит `onDominantChanged`.
- `Enemies/Metamorph.cs` (или имя) — **новый** слушатель ре-диспатча.

- `CreatureBody.Affinity.cs` — поле `startAffinity`, инициализация родства ко всем НЕ-своим видам.

## 5. Риски / гочи
- **Источник «всех видов»** для `donors=все`: рантайм-реестр `SpeciesSO` (бутстрап создаёт .asset в `Data`)? `Resources.LoadAll` / сериализованный список / спавнер знает пул. Уточнить в плане.
- **Грант — выбор слота/варианта:** найти у убийцы слот под тип органа жертвы + индекс варианта её вида (`donors=все` → вариант присутствует). Прицельно по виду жертвы, не рероллом.
- **Регресс баланса:** `donors=все` + `startAffinity` меняют экономику ВСЕХ тел (в т.ч. как чистые NPC считают состав/доминанту). При `startAffinity=1` чистый волк всё ещё доминанта-Волк (родство ≠ идентичность-состав) — проверить, что `MostKin` чистых не поехал.
- **`Install` гранта — выбор слота/варианта:** найти у убийцы слот под тип органа жертвы + индекс варианта вида жертвы. Механика `Install(slotIndex, variantIndex)` — нужен поиск нужного варианта (как тест-химера рероллит, но прицельно по виду жертвы).
- **Дёрганье психики** на границе: гистерезис Medium + трекинг «прошлой доминанты» — проверить, что метаморфоза не зацикливается (туда-сюда). Возможно — кулдаун на смену.
- **tint всех NPC vs Telegraph:** развязка Rebase готова, но проверить на живом NPC (волк телеграфирует + тинтится) — регресс леса.
- **Производительность:** грант в `CreditKiller` (на смерть, редко) — дёшево. Трекинг доминанты в `Recompute` (на смену состава) — дёшево.
- **Высокая динамика → хаос:** лес может быстро выродиться в кашу химер. Это ОЖИДАЕМО (увидеть механику); баланс — потом. Дев-тумблер «скорость химеризации» в панель — удобно для наблюдения.

## 6. Верификация (плейтест)
1. **Грант работает:** NPC-хищник убивает чужой вид → иногда надевает его орган (лог/ридаут состава меняется; цвет плывёт).
2. **Динамика видна:** при высокой вероятности лес за минуты обрастает химерами (волки с иглами, змеи с рогами…).
3. **Ре-диспатч:** NPC, набравший чужих органов до доминанты Medium+, МЕНЯЕТ психику (волк, обожравшийся ежей → ведёт себя как ёж: клубок/залп). Лог смены.
4. **Шасси-якорь:** физически остаётся собой (габариты/слоты шасси), но психика/узнавание/цвет — по доминанте.
5. **Лось эволюционирует** через убийство рогами (реже, но происходит).
6. **Регресс:** обычный бой/стая/узнавание не сломались (tint NPC + грант не задели базовую механику).
7. **Витрина:** удаётся дождаться/подсмотреть многосоставную химеру (стелс-лось-дредноут или подобное).

## 7. Порядок слайса
1. **`AddDonor` (с сохранением состава) + tint NPC** — чистые виды как раньше (`donors=[]`, родные надеты); платформа готова; регресс леса.
2. **Открытие ветки + грант органа** (модуль `CreatureBody.Evolution.cs`, вызов из `CreditKiller`: `AddDonor` вида трупа + шанс `Install`) — химеризация на убийство; плейтест динамики.
3. **Ре-диспатч психики** (трекинг доминанты + `onDominantChanged` + `Metamorph`) — метаморфоза по составу; плейтест смены поведения.
4. Дев-тумблер скорости химеризации (наблюдение) — опц.
5. Коммиты раздельно: платформа-NPC / грант-химеризации / ре-диспатч-метаморфоза.
