# CHIMERA — #2A: провизия приёмов из данных (захват / клубок / масса)

- **Дата:** 2026-07-29
- **Статус:** спека слайса (implementation-oriented). Часть направления «тело=данные», тип A (см. `2026-07-28-arhitektura-tri-osi-refaktor.md`).
- **Родилось из:** брейншторма после закрытия рефактора ядра #1. Survey кода + карта органных фич (диаграмма брейншторма) показали: слой СТАТОВ приёмов уже data-driven, а слой ПРОВИЗИИ (кто создаёт сам компонент-приём) расколот — у игрока из флагов тела, у NPC психика `AddComponent`-ит и настраивает сама.

## 0. Мотивация: два слоя способности

У каждого приёма два слоя. **СТАТЫ** (числа/эффекты: урон, яд, дальности, флаги-эффекты) — идут через `Contribution`/`Recompute`/`OnBodyStats`, **уже data-driven у всех**. **ПРОВИЗИЯ** (кто создаёт и капит компонент-машину) — **расколота**: игроку компонент вешает тело из флагов органа, NPC — каждая психика сама. Для большинства приёмов раскол безвреден (статы из данных, лишний компонент простаивает). Но в трёх местах он ломает химеру-NPC и вешает свойства тела мимо данных.

## 1. Scope (что закрываем)

1. **Захват** — кап стадии психика прошивает руками (волк/ёж 1, змея 3), игнорируя `nativeChassis`; каждая психика сама `AddComponent<Constrict>`.
2. **Клубок** — `CurlDefense` не имеет флага в `Organ` вообще; психика ежа `AddComponent`-ит его.
3. **Масса** — `Massive` вешается на ПРЕФАБЕ (`MoosePrefab`/`WerewolfPrefab`), не из данных шасси.
4. **Таран-по-массе** (райдер к 3) — отброс тарана завязать на массивность САМОГО таранящего.

## 1-бис. Осознанно НЕ трогаем

- **Роли способностей** → #4. Потребитель ролей — женерик-психика, которой ещё нет; тег без потребителя = абстракция в ящик. (Диаграмма брейншторма №2 рисует роли внутри женерик-ядра — они принадлежат #4.)
- **Полная унификация провизии NPC** (bite/leap психика-сайд) — безвредна, едет с #4.
- **`ConfigureHolder`** (escapeMin/Max, порог срыва) — ощущение хвата, не грейд; носителей мало, оставляем на драйвере/префабе (потянем в данные, если заболит).
- **Тип-B** (`GetComponentInParent<XxxPsyche>` ×15) → отдельный заход к #4.

## 2. Захват → данные

**Новое поле `Organ`:**
```csharp
public int constrictStage;  // родная сила захвата органа (1–3); 0 = не грэпл-орган
```

**Правило капа** (тело считает, кормит `SetMaxStage` — и игроку, И NPC):
```
cap = (орган нативен для шасси) ? constrictStage : min(2, constrictStage)
```
«Нативен» = `organ.nativeChassis` пусто ИЛИ == `chassis.speciesName`. При нескольких грэпл-органах — max получившихся капов.

**Раскладка носителей:**

| Грэпл-орган | `constrictStage` | `nativeChassis` | На своём шасси | Украден игроком (человек) |
|---|---|---|---|---|
| Хвост змеи | 3 | Змея | **3** (партер+чок) | min(2,3) = **2** ← как сейчас |
| Пасть волка | 1 | Волк | **1** (плоский хват) | min(2,1) = **1** |
| Цепкая пасть ежа | 1 | Ёж | **1** | min(2,1) = **1** |

Это **обобщает** нынешний `native?3:2` (снейк-эталон байт-в-байт) и ловит волк/ёж=1 без исключений.

**Провизия:** тело (`Recompute`) при `constrictOn` гарантирует наличие машины `Constrict` и зовёт `SetMaxStage(cap)` — для NPC так же, как уже делает для игрока (через `PlayerConstrict`). Психики перестают `AddComponent<Constrict>` и `SetMaxStage`; берут машину ленивым `GetComponent` (тело её создаёт к `Start`/`Recompute`, до первого хвата), оставляют `ConfigureHolder` (ощущение) и драйв (`Begin`/`Tick`/`End`).

**Носители грэпла:** Хвост змеи (есть), **Пасть волка** (добавить `enablesConstrict`+`constrictStage=1` — та же челюсть, что кусает/воет), **Цепкая пасть ежа** (добавить `enablesConstrict`+`constrictStage=1` — та же челюсть, что кусает прижатую добычу). Укус остаётся общим `BiteAbility` (машина захвата намеренно не кусает — «яд/урон льёт драйвер»).

**Бонус:** игрок, надев Пасть волка, получает грэпл (ст.1) — «кража волчьего грэпла» из направления-спеки.

## 3. Клубок → данные

**Новое поле `Organ`:**
```csharp
public bool enablesCurl;  // КЛУБОК (CurlDefense): свернуться в шар — броня↑, катание. chassisOnly (целостная форма тела)
```

**Носитель:** новый `chassisOnly`-орган на шасси ежа (параллель змеиному «Тело-хвост»): напр. «Игольчатое тело», slot="Тело", `chassisOnly=true`, `enablesCurl=true`. `chassisOnly` = не крадётся аугументом (свернуться в шар — свойство целого тела, не болтается на человечий торс); клубок появится у игрока только на ежином ШАССИ (задел смены шасси).

**Провизия:** тело при `curlOn` вешает `CurlDefense` (паттерн `Set*`-маркера / как провизия `constrictAb`). `HedgehogPsyche` перестаёт `AddComponent<CurlDefense>`, берёт ленивым `GetComponent`, драйвит (когда свернуться/катиться — остаётся поведением психики).

## 4. Масса → данные

**Новое поле `SpeciesSO`** (свойство ШАССИ, не органа):
```csharp
public bool massive;  // массивная туша: обхват на стадию слабее, нокбэк не берёт, стае нужно больше
```

**Провизия:** тело при `chassis.massive` вешает маркер `Massive` (паттерн `Set*`: `SetMassive(bool)`). Потребители (`Knockback.Push`, `Constrict.Begin`, `WolfPsyche.RequiredPack`, `SnakePsyche`, `CreditKiller`) уже чекают `GetComponent<Massive>()` — не меняются.

**Носитель — только Лось** (у него СВОЁ шасси `Лось`): `Лось.massive=true`, убрать `AddComponent<Massive>()` из `MoosePrefab`. **Вервольф остаётся с префаб-`Massive`**: он стоит на ЧЕЛОВЕЧЬЕМ шасси (+ все волчьи аугументы, `installAllBeast`) — флаг на шасси `Человек` сделал бы массивным ИГРОКА. Вервольф задумывался супер-химерой; его уникальные боссовые механики (и, возможно, своё шасси) обыграем при плотном заходе на босса (#4). Босс — hand-crafted префаб (как `SuperBossReward`), префаб-провизия для него законна.

**Обоснование (резолвнуто — оставляем):** носителей массивности сейчас нет кроме Лося, но это НЕ преждевременная абстракция — массивность формально такое же свойство ШАССИ, как `nativeChassis` (идентичность) или мощь (состав), просто выраженное **физической характеристикой**, а не принадлежностью к виду. Так она встаёт в тот же ряд «свойства тела, модулирующие приёмы». Это **одно конкретное поле в общем ряду, не фреймворк** (линза подсказывает, ГДЕ массе жить, не заставляя строить абстракцию). Массивное шасси — легитимная тулкит-ось с плюсами (не откидывается, хват слабее, таран сносит) и минусами (стае нужно меньше народу против лёгких — массив собирает толпу) — часть тулкита лося.

## 5. Таран-по-массе (райдер к 3)

`ChargeAbility` при ударе читает СВОЙ `GetComponent<Massive>()`: **есть масса → отброс; нет → без отброса** (урон/стаггер остаются). Zero новой архитектуры — приём просто читает своё тело. **Независим от п.3:** работает и с префаб-`Massive`, и с флаговым — как повешен, всё равно. То есть таран можно сделать, даже если п.3 отложим.

**Развилка (тюнинг, не архитектура):**
- **(б, дефолт)** масса даёт ПОЛНЫЙ отброс, лёгкое тело — слабый базовый толчок (таран игрока не гаснет в ноль).
- (а) бинарно: масса → отброс, иначе 0.

Дефолт (б); финальное число — на плейтесте. Следствие: таран игрока на человечьем шасси станет толкать слабее (нужна масса, чтобы снести с ног) — биологически честно, тюнингуемо.

## 7. Риски / гочи

- **Гоча нового поля (0 в неперегенерённом ассете):** `constrictStage`/`enablesCurl`/`massive` придут нулём до бутстрапа. Но `enablesConstrict`/`enablesCurl` ставятся тем же бутстрапом — грэпл/клубок просто не включатся до «Создать виды», окна «сильнее чем надо» нет. `constrictStage≤0` у грэпл-органа читать дефолтом (напр. 3 = старое нативное поведение) на всякий; выводить в дев-панель.
- **Порядок жизненного цикла:** `Recompute` (Start) идёт после Awake психик. Провизию машин психики берут ЛЕНИВО (`GetComponent` при первом хвате) — к тому времени тело их создало. Паттерн уже есть (`GrabMachine`/`Breath` ленивые).
- **Поведение-сохраняюще:** после слайса NPC должны драться идентично (кроме намеренного таран-по-массе). Змея-эталон — контрольная (её кап 3 не должен измениться).
- **`Massive` и общее шасси:** флаг `massive` — только на шасси, у которого НЕТ не-массивных носителей (Лось — да; Волк/Человек — нет, иначе спилл на всех волков/игрока). Вервольф остаётся префаб-`Massive`. При переносе лося сверить, что он остаётся массивным (иначе его внезапно начнёт откидывать/выбирать змея).

## 8. Верификация (плейтест-чекпоинты)

Инкрементально, каждый под-шаг — играбелен, стоп-Play → пересборка → Play:

1. **Захват-данные:** змея душит как раньше (ст.3 дома); волк/ёж пинят (ст.1); **игрок с Пастью волка хватает** (ст.1). Кап у всех верный, срывы/спасатели работают.
2. **Клубок-данные:** ёж сворачивается/катится как раньше; снятие ежиного «тела» (dev) → клубок пропал.
3. **Масса-данные:** лось/вервольф не откидываются, стае нужно больше, змея их не выбирает — как раньше; `Massive` виден компонентом в рантайме.
4. **Таран-по-массе:** лось-таран отбрасывает; таран игрока (человек) — слабее/без отброса по выбранному тюнингу.

## 9. Порядок слайса

Разбить на под-шаги с чекпоинтами (детализируется в плане реализации):
1. Поля данных + бутстрап (захват-грейд, клубок-орган, масса-флаг) — без смены проводки; проверить, что ничего не сломалось.
2. Захват: провизия+кап из тела, психики на `GetComponent`.
3. Клубок: провизия из тела, ёж на `GetComponent`.
4. Масса: провизия из флага, убрать из генераторов; таран-по-массе.

Каждый — отдельный тематический коммит после плейтеста.
