# CHIMERA — Архитектурное направление: «тело = данные», три оси и рефактор

- **Дата:** 2026-07-28
- **Статус:** НАПРАВЛЕНИЕ (не implementation-спека). Фиксирует картину и порядок работ после закрытия ежа. Каждый слайс получит свою спеку/план перед кодом.
- **Родилось из:** брейншторма после ежа (пользователь накидал 4 идеи; свели к одной картине + рефактору).

## 0. Контекст

Лес почти собран (волк/змея/лось/ёж; сова — последний, большой заход). Ёж вскрыл, что часть функционала **захардкожена в видах**. Пользователь предложил обобщить. Свели к тому, что это не 4 разных задачи, а **одна картина** («тело=данные» имеет три оси вывода) + **рефактор ядра**, который её включает.

## 1. Картина: «тело = данные» → ТРИ ОСИ

Из одного входа `шасси + органы × идентичность/экспрессия` `CreatureBody` (компилятор) собирает три оси:

| Ось | Собирается из тех же частей | Статус |
|---|---|---|
| **1. Функции** (статы, приёмы, чувства) | шасси+органы×экспрессия | работает, но частично захардкожено (см. §2) |
| **2. Морфология** (модель тела) | те же части | задел (голова вервольфа `AttachWolfHead`); отдельная спека (§5) |
| **3. Поведение** (психика) | идентичность/состав | 0 носителей женерик-психики; цель (§4) |

**Симметрия (ключевая идея пользователя):** тело = `шасси + модули-органы`; психика = `женерик-ядро + модули-поведения`. Обе оси — композиция из идентичности. Психика — последняя ось, где вид ещё захардкожен, а не собран из частей. В нашей модели **базовый волк — уже химера с одними волчьими органами**; осталось достроить это до психики.

## 2. Два типа захардкоженного (survey кода)

Сканирование `Scripts/` дало ДВА разных типа (не один):

### Тип A — проводка способности В ПСИХИКЕ (должно быть флагом органа/шасси)
- ✅ **данные (эталон):** флаги `enables*` (укус/таран/рога/рёв/пинок/перекат/залп…); **Хвост змеи** (`enablesConstrict` + `nativeChassis="Змея"` → ст.3 удушения); **нокбэк** уже за `Massive` (резист на приёмнике).
- ⚠️ **хардкод:** захват волка (`Constrict` создаёт `WolfPsyche`, ст.1); захват ежа (то же, `HedgehogPsyche`, ст.1); клубок/катание ежа (`CurlDefense` вешает психика).
- **→ в данные:** NPC-захват = флаг `enablesConstrict` + грейд стадии в данных (как Хвост; волк/ёж = ст.1). Бонус — игрок сможет **красть волчий грэпл**. Клубок = `chassisOnly`-орган (как «Тело-хвост» змеи). Правило трёх: Хвост + волк + ёж = три примера «нативная способность по шасси».

### Тип B — проверка ВИДА в поведении (должно быть предикатом идентичности)
- ⚠️ **хардкод:** `GetComponentInParent<SnakePsyche/MoosePsyche/WolfPsyche/HedgehogPsyche>` — **15+ мест**: волк ищет змею/ежа/лося по ТИПУ психики; `KinVoice`/`PlayerHowl` диспатчат по типу.
- ✅ **уже починили:** `HedgehogPsyche.ThreatsNear` — через `CreatureBody.Regard` + `chassis.eatsMeat`, не по типу.
- **💥 КЛЮЧ:** тип B — самый большой surface И **мост к живому лесу/#4**. Химера-NPC **не имеет** одного `XxxPsyche` → каждый type-check по виду об неё **ломается**. Значит поведение ОБЯЗАНО стать data-driven по идентичности, ПРЕЖДЕ чем в сцену придут животные-химеры (GDD §11).

## 3. Приоритетная последовательность (согласована с пользователем)

1. **#1 — рефактор `CreatureBody`** (фундамент; §4).
2. **#2A — захват в данные** (попутно с #1; тип A).
3. **#3 — спека интерфейса морфологии** (spec-first, меж-командно; §5) — позже.
4. **#4 — женерик-психика ядро+модули** (§6) — самый рискованный, инкрементально, с химеры.
5. **Тип B** — большой заход, мост к #4/живому лесу; держать в голове, не хвататься сразу.

## 4. #1 — Рефактор CreatureBody (следующий)

**Проблема:** `CreatureBody` — компилятор всех осей, разросся, несёт много ролей: слоты, правило экспрессии (`Express`+`Contribution`), агрегатор (`Recompute`), раздача результата по компонентам, родство (`Regard`/`Identity`/`CreditKiller`), метаболизм. Править один модуль = дышать на весь файл.

**Риск:** ЦЕНТРАЛЬНЫЙ файл, тестов НЕТ (верификация только плейтестом). Big-bang рерайт уронит всё молча.

**Метод:** только ИНКРЕМЕНТАЛЬНО, по одному связному шву, каждый — с плейтест-чекпоинтом, поведение-сохраняюще. Естественные швы:
1. **Движок экспрессии** — `Express` + `Contribution` + `Recompute`-агрегация → выдаёт «результат сборки» (struct);
2. **Applier** — берёт результат, раздаёт по компонентам (health/stamina/abilities/senses);
3. **Родство/идентичность** — `Regard`/`Identity`/`CreditKiller`/аффинити;
4. **Слоты/конструктор** — `Install`/`Remove`/`GetVariants`.

**Прорезать шов заранее (под #4):** способности должны уметь **объявлять РОЛЬ** (дальняя/ближняя/захват/рывок/режим-оборона), а тело — отдавать «список способностей». Тогда женерик-психика сядет на готовое, а не будем ломать ядро повторно.

## 5. #3 — Модульная морфология (позже, спека)

Модель собирается из частей (шасси+органы), реперные точки — виды, бленд по экспрессии/идентичности. Две стороны: **мы** проектируем интерфейс-скелет (крючки-API от `CreatureBody`/шасси/органов: точки крепления + идентичность части + бленд), **другой чат** делает меши. Носитель пока один (голова вервольфа) → контракт держать тонким и инкрементальным. Spec-first. После #1 (сядет на чистое ядро).

## 6. #4 — Женерик-психика: ЯДРО + МОДУЛИ (симметрия с телом)

**Форма (важно):** НЕ расплющить всё в один женерик-выбиратель (потеряем стайные жетоны/засаду/лесенки), а **тонкое ядро + подключаемые модули поведения**:
- **ядро** (общее): опрос способностей по ролям + `Regard` по идентичности + выбор «что делать по ситуации» (для первой химеры — простой приоритет-список, НЕ utility-AI);
- **модули** (цепляются по идентичности): стая, засада, лесенка-предупреждений (лось), лестница-отчаяния (ёж), альфа-агрессия (химера).

**Тир-разделение снято (поправка пользователя, принята):** не «бесбоук vs женерик» два тира, а ЕДИНОЕ ядро+модули для всех. Волк = ядро+стая, ёж = ядро+лестница, химера = ядро+альфа.

**Payoff — стохастическая химеризация:** мутировал орган у NPC → женерик-ядро сразу им пользуется (мутант оживает без ручного кода); модуль цепляется по идентичности. Оживляет экосистему (GDD §11 «эволюция видов»). Ради этого и стоит.

**Правило трёх:** модули уже существуют, вварены в монолитные психики (стая волка, засада змеи, лесенка лося, лестница ежа = 4 кандидата) → извлечение обосновано.

**Метод:** носитель-first — ядро рождается НА ХИМЕРЕ (первый носитель женерик-поведения), маленькое, проверяемое. Потом извлекаем модули по одному, каждый с плейтест-чекпоинтом, сверяясь, что волк/змея/лось/ёж не потеряли повадки.

**Честная оговорка:** какой-нибудь модуль (стая завязана на общий `PackCoordinator`, шаренное состояние) может упереться в связность — вскроем при извлечении, подстроимся. Прецедент тела обнадёживает (универсализация не убила флейвор), но поведение коварнее статов.

**#4-бис (разворот пользователя):** психику не ДРОБИТЬ, а ПОДКЛЮЧАТЬ модулем по факту идентичности — это и есть «ядро+модули». Согласуется.

## 7. На карандаш / открытое

- **Химера-психика = альфа-хищник**, чуждый всем (грань идентичности «химера»). Первый носитель женерик-ядра. Приходит с животными-химерами в сцене (живой лес).
- **Utility-AI** (мораль×голод×дистанция×личность → выбор) — зрелая форма женерик-ядра; строить, когда носителей ≥3. Пока — приоритет-список.
- **Смена шасси игрока** (post-MVP) — та же ось «нативные способности по шасси», дозреет с ней.
