# Форма химер по шаблонам типов тела: решение консилиума

- **Дата:** 2026-10-21
- **Статус:** В РАБОТЕ · решения ДЕЙСТВУЮТ (геймдизайнер 20–21.10, ответы на доске `q-kons-*`, `q-telo-st2-kolonka`). В коде: слой позы `KeyPose` (21.10); шаблон К2 с петлями, новая подгонка и ключи — на ветке модельной линии, в main не поставлены
- **Отменяет:** —
- **Родители:** сводка консилиума `Docs/models/konsilium-forma-2026-10-20/SVODKA.md` (направления А–Д, Г — `Г-kod.md`, Д — `D-dizajn.md`); `2026-10-09-chistyj-vid-meshem.md` (вид — мешем, химера — кусками; остаётся); `2026-09-27-smeshenie-siluetnogo-grafa.md` (два слоя тела: аугмент локально, идентичность глобально; поза — глобальный слой; решение 5 «Сердце меняет грудную клетку локально»)

## 1. Вопрос

Лес химеризуется сам, поэтому хранить готовую фигуру на каждую комбинацию нельзя (геймдизайнер 20.10: «хранить бесчисленное
число комбинаций тяжко будет, это про будущие риски»). Перенос цели ступени 2 на сетку человека К2 («тонкая пластина по
суставам + ближайшая точка») давал «плиту плеч, горб, торс коробкой». Консилиум из пяти направлений искал схему, которая
растёт по видам, а не по комбинациям.

## 2. Решения

1. **Шаблон тела = шасси, один на ТИП ТЕЛА** (геймдизайнер 20.10: «с шаблоном на типы тела согласен»):

   | тип тела | виды | шаблон |
   |---|---|---|
   | двуногий | человек | К2 с петлями под шесть областей масс (Д) |
   | четвероногий | волк, лось, Хеджхалк | сетка волка; лось перестраивается на неё, Хеджхалк делается сразу на ней |
   | змеиный | змея | её меш |

   Формы видов на чужом типе тела (волк-двуногий) — формы на сетке шаблона этого типа. Хранится O(виды × типы тела), а не O(виды²).
2. **Ключ пары вычисляется на общей сетке**, а не переносится. Подгонка цели — поза скелетом → соответствия по частям тела
   → non-rigid ICP (направление Б), а не ближайшая точка. Проверено 20–21.10: подгонка по частям + уплотнённая К2 сходятся с
   целью в 1–3 см по силуэту.
3. **Три слоя глобальной формы** (А, В): длины — суставами (`KeySkeleton`), **поза — поворотом костей** (`KeyPose`, решение «Б»
   21.10: ключ несёт форму в покое, сутулость и согнутые колени — кости), масса — формой-ключом. Детали — кусками органов.
4. **Глобальную форму даёт одна доминанта** (≥ 0.65). Геймдизайнер 20.10: «мы взяли это как структурное правило построения
   тел, оно не записано отдельно, а выведено в нашем DSL по факту. Идентичность имеет значимый смысл, это не просто число —
   она влияет на интеграцию существа в экосистему». Второй донор виден только органами. Смесь глобальных форм не вводится.
5. **Торс меняется по областям масс** (подход дизайна Д: грудь; грудь–живот–таз; лопатки и плечи раздельно; шея и посадка
   головы; длины и основания конечностей; переходы с просветами) — ключом поверх костей, а не сменным куском донора.
   Геймдизайнер 20.10: «видимо, подход дизайнера будет логичнее». **Открыто:** орган Сердце должен быть виден формой грудной
   клетки (решение 5 спеки двух слоёв). На шаблоне это ложится как **ключ области**: форма грудной клетки донора Сердца —
   на вершинах области «грудь» поверх глобального ключа. Как именно они складываются, решится, когда дойдём до Сердца.
6. **Звериные химеры (волк ↔ лось ↔ Хеджхалк) — вторым шагом**: «думаю, сначала закроем человека».
7. **Общие швы** (шея, запястье, щиколотка, основание хвоста) — одинаковое число вершин во всех шаблонах: кусок с одного типа
   тела садится на другой вершина в вершину. Уплотнение К2 швы не трогает (проверено 21.10).
8. **Цель голого тела оборотня ст.2** — `Референсы/витрина/оборотень/тело.png` (дизайн по колонке ст.2, принято 21.10: «да,
   так лучше»). Длины ноги и угол колена — с неё.

## 3. Порядок работ

1. Оборотень на уплотнённой К2: 3D-цель по `тело.png` → подгонка → ключ «Волк», поза, суставы; голова по колонке ст.2 — кусок.
2. Человек-лось тем же методом. 3. Человек-Хеджхалк. 4. Лось на сетке волка, затем звериные химеры.

Поставка в main — одним заходом на тип тела (уплотнённая К2 меняет индексы вершин внутри объектов, старые ключи с ней не
живут): ключи Волк и Лось, позы, суставы, головы; объекты `@Волк`/`@Волк1` старой схемы снимаются, `KeyStageTests` переписываются.
