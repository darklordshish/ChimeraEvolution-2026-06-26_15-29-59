# CHIMERA — Морфология химер (минимальная, из данных)

- **Дата:** 2026-07-31
- **Статус:** спека слайса (implementation-oriented). Ось 2 «модель из состава» (см. `2026-07-28-arhitektura-tri-osi-refaktor.md`). Роадмап: эволюция NPC ✅ → **морфология** → #4b-4 боссовость.
- **Родилось из:** брейншторма 2026-07-31. Мотив: химеры нечитаемы, **цвета-по-составу мало** — надо видеть, ИЗ ЧЕГО собрана тварь. Разграничение зон: **структуру берёт Claude** (скелет/места/сборка/кубы), модельному чату — красота/смешение потом. См. [[chimera-morfologiya]].

## 0. Контекст

Тело=данные дало функции (✅) и психику-по-составу (✅ #4b + эволюция). Морфология — **третья ось**: модель тоже выводится из `шасси+органы`. Сейчас модель — статичные кубы (`WolfPrefab.BuildBlocky`), не связанные с органами; единственная связь состав→визуал — цвет (`CompositionTint`). Морфология добавляет **форму**: орган → видимая куб-часть, собирается в рантайме, **пересобирается при эволюции**.

## 1. Scope

**Минимальная морфология-из-данных на паре Волк + Человек, проверка — вервольф** (человек-шасси + волчьи органы = узнаваемый результат + конфликт «волчьи части на прямоходящем скелете»). Кубы грубо (габариты/углы/место), БЕЗ подгонки. Кин-окрашивание (`CompositionTint`) поверх. Остальные виды, красота, анимация — НЕ здесь.

## 2. Дизайн

### 2.1 Данные — два слоя (выбор пользователя: «в данных органа»)
- **`Organ.visual`** (у ВИДИМЫХ органов; внутренние Сердце/Чутьё — без визуала): описание куб-части —
  - `part` — тип якоря (по смыслу слота: Пасть→морда, Руки→передние конечности, Ноги→ходовая, Хвост→хвост, Шкура/Иглы→корпус-поверх, Рога→макушка, Голова человека→голова);
  - `scale`/пропорции куба, локальное смещение/поворот от якоря;
  - цвет — из тинта вида (`SpeciesTint`), поверх — `CompositionTint`.
- **`SpeciesSO.skeleton`** — набор **якорей**: именованная точка (`part` → локальная позиция + базовый габарит), заданная под РОСТ/позу вида. Человек — прямоходящие якоря (голова вверху, руки по бокам, 2 ноги); Волк — четвероногие (морда впереди-низко, 4 лапы, хвост сзади).

### 2.2 Сборка в рантайме (`MorphBuilder`)
Компонент/хелпер: по надетым органам тела создаёт дочерние кубы-части на якорях **СВОЕГО шасси** (скелет от шасси, форма от органа). Зовётся из `Recompute` (или подписан на смену состава) → эволюция сменила орган → модель **пересобирается сама**. Старые части сносятся, новые строятся (или диф). Эмерджентность: волчья морда (орган) на **человечьем** якоре-голове = морда вервольфа; на волчьем якоре — обычная волчья морда.

### 2.3 Конфликт расположения (шасси-фёрст + слот→якорь)
- **Кросс-шасси:** орган ищет якорь шасси по своему `part`. Волчий орган «Пасть» → якорь `голова`/`морда` шасси (у человека это голова прямоходящего). Так волчьи части ложатся на человечьи якоря = вервольф.
- **Дублирование** (родной орган + химерный того же `part`): рисуем ОДИН — **шасси-фёрст** (родной), химерный дубль скрыт (на первое время; потом иначе).
- **Нет якоря под `part`** (у шасси нет такого места) → часть не рисуется (как игломёт лосю — нет слота, так и нет якоря). Форм-лимит по шасси — консистентно с механикой органов.

### 2.4 Кин-окрашивание — поверх
`CompositionTint` (готов) красит собранные части. Морфология = форма, тинт = цвет. Части рендерятся `MeshRenderer` (примитивы-кубы) → тинт через MPB, как сейчас. Развязка с `Telegraph.Rebase` (готова) сохраняется.

### 2.5 Вернуть кубические Волка и Человека
Для однообразия языка сборки — отключить FBX (`WolfPrefab.TryAttachModel`), использовать кубы (`BuildBlocky`/`AttachWolfHead` — Claude их строил). Идеал: старый `BuildBlocky` заменяется сборкой из §2.2 (кубы-части = органы), но для первого слайса можно оставить BuildBlocky как fallback-визуал шасси, а органы-части накладывать поверх.

## 3. НЕ в этом слайсе
- **Остальные виды** (Змея/Лось/Ёж скелеты+визуал органов) — следом.
- **Красота и смешение морфологий** — модельный чат (плавные переходы, скин──меши, риги).
- **Анимация/позы** (боди-ленгвидж) — отдельная ось.
- **Точная подгонка** частей (стыки/пропорции) — грубо кубами пока.
- **Химерный слот в морфологии** (орган вне формы шасси визуально) — когда дадим химерный слот NPC.

## 4. Точки касания
- `SpeciesSO.cs` / `Organ` — поля `skeleton` (якоря шасси) и `visual` (куб-часть органа).
- Новый `MorphBuilder` (`Player/` или `_Chimera/Scripts/Morph/`) — рантайм-сборка из состава.
- `CreatureBody` — зовёт `MorphBuilder` в `Recompute` (пересборка при смене состава); рендереры частей идут в `renderers` для тинта.
- `Editor/WolfPrefab.cs`, `WerewolfPrefab.cs` — вернуть кубы / убрать хардкод `AttachWolfHead` (обобщён морфологией).
- `SpeciesBootstrap.cs` — заполнить skeleton/visual для Волка и Человека (⚠️ переген «Создать дефолтные виды» + Ctrl+S).

## 5. Риски / гочи
- **Скелет человека ≠ волка** (прямоходящий vs четвероногий) — конфликт: волчьи 4 лапы на 2 человечьих якорях. Решение: `part` маппит по СМЫСЛУ (передние конечности → руки, задние → ноги), шасси-якорь даёт позу. Проверить, что вервольф выходит узнаваемым, а не месивом.
- **Пересборка модели каждый `Recompute`** — при эволюции часто; снос/постройка кубов — не бесплатно. Диф (менять только изменённые части) или троттлинг — если профайлер укажет.
- **`renderers` для тинта** — сейчас собраны в `Awake`; части создаются позже (рантайм) → надо пере-собирать список `renderers` после сборки морфологии (как `Telegraph.Rebase`).
- **Вервольф `installAllBeast`** — все волчьи органы надеты с рождения → морфология соберёт полный набор волчьих частей на человеке. Хороший тест, но проверить, что человечьи «вытесненные» части не дублируются с волчьими.
- **Бутстрап-гоча** (новые поля skeleton/visual) — переген видов обязателен, иначе поля пустые ([[chimera-bootstrap-gate]]).
- **Модельная зона:** префабы Волка/Вервольфа пересобираются генераторами; координация с модельным чатом (кубы vs FBX) — не наступить на их FBX.

## 6. Верификация (плейтест)
1. **Вервольф собран из частей:** спавн вервольфа (dev-панель) — тело собрано морфологией из данных (человечий скелет + волчьи морда/лапы/хвост/шкура), узнаваемо, не месиво.
2. **Чистый волк** — волчьи части на волчьем скелете (обычный волк как раньше, но из органов-частей).
3. **Динамика:** химеризуй человека/волка (эволюция или конструктор) — части **появляются/меняются на лету** (нарос волчий хвост → хвост возник).
4. **Форм-лимит:** орган без якоря под свой `part` — часть не появляется (не падает).
5. **Тинт:** части красятся по составу (`CompositionTint`), телеграфы работают (Rebase).

## 7. Порядок слайса
1. Данные: `Organ.visual` + `SpeciesSO.skeleton` (поля + заполнить Волк/Человек в бутстрапе).
2. `MorphBuilder` — сборка из состава на якорях шасси; пере-сбор `renderers`.
3. Вызов из `Recompute` (пересборка при эволюции); вернуть кубы Волк/Человек.
4. Плейтест: вервольф из данных + динамика химеризации.
5. Коммиты: данные-морфологии / MorphBuilder-сборка / интеграция+кубы.

## 8. ЗАДЕЛ
- **Остальные виды** (скелеты+визуал) — по одному, как расширение.
- **#4b-4 БОССОВОСТЬ:** супер-химера-босс на готовом — морфология (эта) + химеризация (эволюция) + модуль боссовости (фазы/вой с вервольфа). `PsycheDispatch` — точка подключения.
- **Красота** (модельный чат): плавные переходы, скин-меши, стыки, риги, анимация-позы — поверх работающей структуры.
