## 0. Контекст: где мы в #4b

#4b-1 дал носитель (тест-химера), #4b-2 — оживление + химера-альфа + тривиальный диспатч (всегда альфа + лог доминанты). **#4b-3 — ПОЛНЫЙ ДИСПАТЧ: доминанта дотянула до вида → его психика-модуль; иначе → альфа.** Плюс поправка узнавания (шасси → доминанта), без которой «волк-по-идентичности» не признают своим.

## 1. Scope #4b-3

1. **Диспатч по доминанте** — `PsycheDispatch` вешает ВИДОВУЮ психику по `MostKin` (Волк/Змея/Лось/Ёж), альфа — только для истинных химер и доминанты-Человек.
2. **Узнавание по составу** — `Regard` смотрит доминанту цели (`MostKin`), не `Chassis`. 3 градации `KinTier` сохранены.
3. **Тип-B замыкается маркером** — видовые prey/threat-чеки работают сами (диспатч повесил психику-маркер). Проверить, не конвертировать.

Носитель — тест-химера #4b-2 (уже спавнится).

## 2. Дизайн

### 2.1 Диспатч по доминанте (`PsycheDispatch.Attach` расширить)
```
dom = body.MostKin(out tier);
psyche = dom?.speciesName switch {
    "Волк" => typeof(WolfPsyche),
    "Змея" => typeof(SnakePsyche),
    "Лось" => typeof(MoosePsyche),
    "Ёж"   => typeof(HedgehogPsyche),
    _      => typeof(ChimeraAlphaPsyche),   // Человек (NPC-психики нет) / истинная химера (dom==null) → апекс
};
body.gameObject.AddComponent(psyche);
body.Refeed();
```
Порог = `Weak` (`MostKin` возвращает `null`, если доминанта не дотянула Weak → истинная химера → альфа). Карта строк — MVP-выбор (виды наперечёт); хрупкость имён — гоча §5.

**Видовые психики само-достраивают зависимости** (`if (!TryGetComponent) AddComponent`: `NavLocomotion`, `Senses`+профиль из полей, доставки, `ScentTrail`, `HeatSignature`, `StunTint`) и учитывают тело (`if CreatureBody == null` — реген свой, иначе из органов). Значит навешивание на химеру-носитель работает без префаба вида — психика достроит себя, профиль возьмёт из дефолтов класса.

### 2.2 Узнавание по составу (`Regard`-поправка)
`CreatureBody.Regard` в `CreatureBody.Identity.cs` — заменить `target.Chassis` на доминанту:
```csharp
public static KinTier Regard(CreatureBody observer, CreatureBody target)
{
    if (observer == null || target == null) return KinTier.None;
    var dom = target.MostKin(out _);  // идентичность цели = ДОМИНАНТА по составу, не шасси
    return dom != null ? observer.Tier(dom) : KinTier.None; // истинная химера (dom==null) → никому не своя
}
```
- волк.`Tier(Волк)` = Strong → волка-по-идентичности признаёт (хоть он на шасси-Человек);
- **чистые виды**: `MostKin == Chassis` → **no-op**, старое поведение цело (главная страховка);
- истинная химера (`MostKin`=null) → `None` ко всем — согласуется с альфой «монстр для всех».

`IsKin` (#4a) зовёт `Regard` → тоже переезжает на состав автоматически. **3 градации на выходе нетронуты** — люфт социального встраивания (кого стая терпит/принимает/держит своим по тиру) настраиваем на балансе позже, НЕ схлопываем в бинарное.

### 2.3 Тип-B замыкается маркером
Видовые prey/threat-чеки (`WolfPsyche.RetargetPrey` ищет `SnakePsyche`/`HedgehogPsyche`; и т.п.) находят цель, раз диспатч повесил на неё видовую психику. Конверсия в предикаты НЕ нужна для межвидового узнавания — маркер решает. **Проверка плейтестом:** волк-по-идентичности охотится на змею-по-идентичности; ёж-по-идентичности пиннит змею; RPS-круг держится среди химер.

### 2.4 Носитель
Тест-химера #4b-2. Диспатч теперь вешает видовую психику вместо всегда-альфы — весь спектр доминант проверяется рероллом состава.

## 5. Риски / гочи
- **Видовая психика ждёт что-то жёстко с префаба** (не `AddComponent`-guard) → NRE на химере. Волк проверен (всё до-создаёт); Змея/Лось/Ёж — проверить плейтестом, при NRE добавить guard в ту психику.
- **`PackCoordinator` / стая:** волк-по-идентичности вливается в стаю (с §2.2 его узнают). Слоты окружения/жетоны — проверить, что химера-волк не ломает координатор.
- **Карта имён-строк** хрупка: переименовали вид → обновить switch. Локализовано в диспатче; вынос в `SpeciesSO` — если понадобится.
- **`Regard` теперь зовёт `MostKin`** (перебор доноров) вместо чтения `Chassis` — чуть дороже. Зовётся психиками периодически (не каждый кадр), приемлемо; кеш `MostKin` в теле — если профайлер укажет.
- **Регресс чистых видов:** `Regard`-поправка для чистых видов no-op, но затрагивает ВСЕ психики → плейтест обычного леса (волки/лоси/ежи/змеи + игрок) на не-сломанность ПЕРЕД доверием.
- **Доминанта-Человек → альфа:** химера с доминантой-Человек ведёт себя как апекс-монстр (человечьей NPC-психики нет) — осознанно.

## 6. Верификация (плейтест)
1. **Диспатч:** спавн химер, в консоли — доминанта → её психика (не «пока альфа»). Ролл даёт волков/змей/лосей/ежей-по-идентичности + истинных химер (альфа).
2. **Видовое поведение:** химера-доминанта-Волк ведёт себя как волк (стая/тень/прыжок); Змея — засада/яд; Ёж — клубок/залп; Лось — берсерк/таран.
3. **Узнавание по составу:** волк-по-идентичности признан обычной стаей (не дерётся с ней); истинная химера — чужая всем.
4. **Тип-B маркер:** волк-по-идентичности охотится на змею-по-идентичности (и наоборот по RPS).
5. **Регресс:** обычный лес (чистые виды + игрок) ведёт себя как раньше — узнавание не сломалось.

## 7. Порядок слайса
1. `Regard`-поправка (Chassis → `MostKin`) — изолированно, регресс чистого леса.
2. `PsycheDispatch` карта доминанта→психика + альфа-фолбэк.
3. Плейтест: диспатч + видовое поведение + тип-B + регресс.
4. Коммит(ы): узнавание-по-составу / диспатч видовых модулей.
