# CHIMERA — Сокет-план тела: единый источник правды для слотов и морфологии

- **Дата:** 2026-08-01
- **Статус:** спека рефактора ядра конструктора. Родилось из наблюдения пользователя по ходу морфологии.
- **Мотив (пользователь):** «унификация разных имён — риск багов при соединении разных аугументов на один слот; тут же всё чётко подогнано, как часовой механизм… единый источник правды — одна структура». Плюс правится ОДИН модуль (`CreatureBody.Slots.cs`), а не весь файл — партиал-split окупается.

## 0. Проблема

Сейчас у тела **два параллельных описания мест**, которые держатся на дисциплине именования:

| Ось | Источник | Имя места |
|---|---|---|
| Механика (что можно надеть) | слоты строятся из `chassis.organs[].slot` | «Руки», «Пасть», «Хвост»… |
| Морфология (где это видно) | `SpeciesSO.skeleton[]` (`SkeletonAnchor.part`) ← `Organ.visualPart` | «передние», «морда», «хвост»… |

Следствия, уже наблюдавшиеся:
- **молчаливые провалы:** опечатка в `visualPart` — деталь просто не рисуется, ошибки нет;
- **химерный слот анатомически «нигде»** — механически принимает что угодно, а места у этого «чего угодно» может не быть → графт невидим;
- **два списка надо синхронизировать руками** при каждом новом виде/органе.

## 1. Модель: сокет-план

**Сокет — место на теле.** Один список на вид, обслуживает ОБЕ оси.

```
BodySocket {
  name        // ИМЯ = Organ.slot («Руки»/«Пасть»/«Хвост»/«Рога»/«Игломёт»…) ИЛИ чисто телесное («голова»/«шея»/«уши»)
  localPos, baseSize, baseEuler, mirrorX   // где на теле и как (mirrorX — пара: 2 руки/4 лапы/2 уха)
  hidden      // ВНУТРЕННИЙ орган (Сердце/Чутьё): слот есть, места на теле нет
  graft       // ЗАКРЫТ у этого шасси («плейсхолдер»): у человека хвост/рога/игломёт
}
```
`SpeciesSO.sockets[]` заменяет `skeleton[]`. **`Organ.visualPart` УДАЛЯЕТСЯ** — имя сокета и есть `Organ.slot`. У органа остаются только `visualScale`/`visualOffset`/`visualEuler` — его форма В СВОЁМ месте.

**Словарь сливается** (визуальные имена вливаются в механические): `передние→Руки`, `задние→Ноги`, `морда→Пасть`, `корпус→Шкура`, `хвост→Хвост`, `рога→Рога`, `иглы→Игломёт`; `голова`/`шея`/`уши` остаются телесными сокетами без органов.

### 1.1 Слоты из сокетов
- сокет **открыт** (не `graft`) и есть органы с таким `slot` → **слот конструктора** (варианты: родной органа шасси + донорские);
- сокет **телесный** (`голова`/`шея`/`уши`, органов нет) → слота нет, рисуется базой;
- сокет **`hidden`** (Сердце/Чутьё) → слот есть, визуала нет;
- сокет **`graft`** → см. 1.2.

### 1.2 Химерный слот — ПЛАВАЮЩИЙ и МОРФНЫЙ (решение пользователя)
Химерный слот **выбирает ОРГАН, а не место**: «любой аугумент, в каком бы слоте он ни стоял». Награда (`chimeraSlots`) — **бюджет**: сколько таких органов можно носить одновременно. Выбирать «какой сокет открыть» не нужно.

Дальше тело само укладывает орган в его **анатомическое место** = сокет с именем его `slot`. Отсюда два случая:
- место **свободно** (у шасси такого сокета нет или он пуст — Хвост/Рога/Игломёт у человека) → орган занимает его;
- место **уже занято** родным органом (волчья Пасть при родном Рте) → **оба живут на одном сокете**.

**ДВОЙНЫЕ АУГУМЕНТЫ СОХРАНЯЮТСЯ ПОЛНОСТЬЮ** (ключевая фича баланса и веселья): механика их уже складывает — вклады группируются по типу слота, величины берутся супремумом, фичи по ИЛИ. Волчья Пасть (вой) + змеиные клыки (яд) = обе фичи, как и было.

**Визуальное правило (временное, согласовано):** на сокете рисуется **ПЕРВИЧНЫЙ** орган — тот, что стоит в РОДНОМ слоте шасси; химерный — вторичный (виден только если родное место пусто). Не хронология, а порядок слотов: стабильно и не требует хранить время установки. Химерный слот по замыслу **МОРФНЫЙ** — два аугумента на одном месте должны давать **слитый дизайн**; слиянием займёмся, когда будет что сливать (нужны меши, а не кубы).

### 1.3 Что НЕ входит: суперхимерный слот
Дублирующие части тела (вторая пасть отдельным наростом, лишние конечности) — это **СУПЕРхимерный** слот, отдельная продвинутая фича. Она решается вместе с задачей **слияния нескольких шасси** и берётся сильно позже. В сокет-плане её место есть (добавятся сокеты-наросты), но сейчас не строим.

## 2. Морфология на сокетах
`MorphBuilder` читает `chassis.sockets`: место занято органом → форма органа (`visualScale/Offset/Euler`); иначе — базовый куб (кроме `hidden` — не рисуется никогда, и `graft` — пустым не рисуется). Если на сокете **два органа** (родной + химерный того же типа) — рисуется первый (§1.2), место под **слияние дизайна** остаётся здесь же.

Выигрыш: место органа больше не задаётся отдельным полем (`visualPart`) — оно **следует из его слота**. Рассинхрон двух списков невозможен by construction.

## 3. НЕ в этом рефакторе
- Меши вместо кубов (модельный чат, свой контракт).
- Остальные виды в морфологию (Змея/Лось/Ёж — свои визуалы).
- Смена шасси игрока (сокет-план — фундамент под неё, но сам переход отдельно).
- **Суперхимерный слот** (дубли частей/лишние конечности) и **слияние дизайна** двух органов на сокете — обе ждут мешей и задачи слияния шасси (§1.3).
- Лицо игрока (глаза/борода) — вернуть деталями позже.

## 4. Точки касания
- `Player/SpeciesSO.cs` — `BodySocket` вместо `SkeletonAnchor`; `sockets[]` вместо `skeleton[]`; убрать `Organ.visualPart`.
- `Player/CreatureBody.Slots.cs` — `BuildSlots` из сокетов; графт-бюджет в `Available`/`CanInstall`; `SlotView` (+признак графта и бюджет для UI).
- `Player/MorphBuilder.cs` — сборка по сокетам.
- `Editor/SpeciesBootstrap.cs` — миграция данных всех видов (⚠️ переген + Ctrl+S).
- `UI/ConstructorUI.cs` — показ графт-сокетов и остатка бюджета (гнёзда, которых нет у шасси).
- `Progression/ChimeraSlotReward.cs`, `CreatureBody.GrantChimeraSlot` — семантика «+1 к бюджету графтов» (счётчик тот же).

## 5. Риски
- **Конструктор — самая выстраданная система** (drag&drop, один-экземпляр, химерные слоты): рефактор ведём слайсами с плейтестом каждого, не одним куском.
- **Индексы слотов** (`Install(slot, variant)`, хоткеи 1–8, UI-строки) поедут — проверить раскладку и UI.
- **Данные всех 5 видов** переписываются разом → обязательный переген и сверка ассетов (гоча бутстрапа).
- **Правило одного экземпляра** (`WornElsewhere`) частично поглощается сокетами — не удалять вслепую, свериться.

2. **Слоты из сокетов:** `BuildSlots` по сокетам, графт-сокеты + бюджет. Проверка: конструктор работает, графты требуют бюджета.
3. **UI:** конструктор показывает графт-гнёзда и остаток бюджета; награда = +1 бюджет.
