# План S5: верификация ландшафта

- **Статус:** **В РАБОТЕ · решения ПРИНЯТЫ и ДЕЙСТВУЮТ (01.11.2026, второй заход)**; открытых развилок
  по силе ворот **нет**: `G7` — **A** (кадр блокирует каждый срез), `G5` — **B** (вода/логова — отчёт и
  долг B1, не блок S3). Приняты гидроэрозия **B** (запекание при старте), плотность **неравномерными
  пятнами** 3000–3500 с оглядкой на рельеф, вода **C** (водопой + тактика), лазание (вертикаль — механика,
  геймплей позже), отмена боевых арен («арены» = лабораторные остовы/антропогенные POI; дороги база →
  ворота → зоны).
- **К спеке:** [`2026-11-01-landshaft-s5-verifikaciya.md`](../specs/2026-11-01-landshaft-s5-verifikaciya.md).
- **Правило:** сначала **прибор и детекторы** (шаги 1–7), потом приёмка S1/S2/S3 (шаги 8–10). Пока
  измеритель не проверен на синтетике, ворота на мир не ставятся.
- **Код в этом заходе не трогается.** План — исполнение будущими срезами, по одному шагу за раз.
- **Числа не дублируются.** Пороги M2–M5 — S1 §6.2, M6/M8 — S2 §1.1/§5.2, M9/M9b — S3/S4, M15 —

  S5 задаёт M3b, M12 (паритет), M14 (пятна) и протокол кадров; всё остальное **берёт**.
- **Профиль ворот — `terrainQuads 48`, всегда.** 16 — только отладочный быстрый прогон при зелёном G0.

## Шаг 1. Прибор: метрики в рантайм, а не в тест

**Почему первым.** S1 §6.2 и его план (шаг 3) заводят сторожа `DomeReliefTests` с метриками полос. Если
метрики останутся **внутри EditMode-теста**, их не увидят PlayMode-ворота: `Chimera.Tests.EditMode` и
`Chimera.Tests.PlayMode` — разные сборки (`Assets/_Chimera/Tests/EditMode/Chimera.Tests.EditMode.asmdef`,
`.../PlayMode/Chimera.Tests.PlayMode.asmdef`). Значит реализация обязана быть **рантайм-кодом**, а тесты —
только вызывать.

**Делаем.** `Assets/_Chimera/Scripts/Forest/Generation/ForestLandscapeMetrics.cs` (новый, рантайм) —
одна реализация M1–M5, M3b, M4b, **M8, M9, M9b, M13–M16** **по формулам S1/S2/S4**, без своей математики:

- `Slope(...)` — `atan‖∇h‖` при двух ε, p50/p95/p99, доли **≤22/22–35/>35**, `max|∇H|` **по форме**,
  отдельно «проходимое», «лазаемое» и «стена»;
- `LongEnergy(...)` — `Var(box250(H0)) / Var(H0)` (S1 §6.2);
- `MesoCoverage(...)` — окно 300×300, `p90−p10 ≥ 12` (S1 §6.2);
- `LocalRelief(...)` — доля диска, где в окне 40 м перепад ≥3 м (M3b, порог S5 — 60 %);
- `Landforms(...)` — `H/D = H/(D − бровка)` — **одно** определение, `D` по подошве, `бровка` — плоский
  верх; `H/W`, `blend/H`, `D/W` — свои параметры, не второй `H/D`; всё **из поля**, не из
  `DomeRelief.State`;
- `Balance(...)` — `P/N` по **объёму** (интеграл `|H|` по пятну) или площади пятен, **не** `ΣP/ΣN`;
- `SeamJump(...)` / `MinCurvatureRadius(...)` — `|Δslope|` на 1 м и радиус (S1 §3.6);
- `ClimbBand(...)` — **M13:** доля 22–35°, длина/высота граней, уступы, обход; `>35°` — стена;
- `ForestPatches(...)` — **M14:** площадь пятен, локальная плотность 3000–3500, крона 13–15 %, глобальная
  плотность — отчёт; запреты (вода, >35°, З1–З13);
- `Roads(...)` — **M15:** компоненты primary POI, петли, уклон/ширина/брод/длина; лента по земле;
- `HydroAsset(...)` — **M16:** ключ `(seed, worldVersion, erosionVersion, resolution)`, хэш ассета,
  `bakeMs`, `hydraulic=ok|missing|timeout`; **не** запускает второе запекание.

Если S1 уже написал это внутри `DomeReliefTests` — **переносим**, а не пишем второй раз. Владелец
формул — S1; владелец класса-носителя — пакет (сводится при приёмке пакета).

**Тест.** `Assets/_Chimera/Tests/EditMode/Forest/Worldgen/ForestLandscapeMetricsTests.cs` (новый) —
проверяет **инструмент на синтетике**, а не мир:

| поле | ожидание |
|---|---|
| плоскость | p50 = p95 = p99 = 0, `E_λ = 0`, мезо 0 |
| один холм с известным `H/D` | `H/D` совпадает ±2 %, `\|∇h\|max = 3H/D` (S1 §3.3) |
| синус `λ = 500 м` | `E_λ ≈ 1` |
| белый шум | `E_λ ≈ 0` |
| гребёнка `λ = 40 м` | излом растёт, `E_λ ≈ 0` |
| синтетическая гряда `W=35, H=4.2` | ≤ 19.8°, а не 70° (эталон S1 плана, шаг 4) |
| монотонность долей | при `p95 ≤ 20°` доля `>22°` **≤ 5 %**; доля `>t` не растёт с `t` — иначе пара ворот G1 невыполнима (§3.1 п. 4 спеки) |
| два холма известного объёма | `P/N` по объёму = 1.00 ± 2 %; по `ΣP/ΣN` тот же вход даёт другое число — тест держит формулу |
| три класса уклона | плоскость → 0 % 22–35° и 0 % >35°; рампа 30° → 100 % в 22–35°, не в стене; стена 45° → 100 % в >35° |
| пятно известной площади | локальная плотность считается по пятну, глобальная — отчёт; 0 стволов в пятне POI/зоны и R12 от осевой, на воде и >35° |
| дорога-ломаная | уклон/ширина/длина по S4; обрыв компоненты ловится; петля без POI не считается петлёй |
| гидро-ключ и fallback | тот же ключ → тот же хэш; нет ассета → `hydraulic=missing`; таймаут → `timeout`; повторный вызов не запекает |

**Ворота.** Все строки зелёные. **Не делать:** не гонять на `ForestBuilder`, не подбирать пороги под
текущий мир, не заводить второй класс метрик.

**Команда:** `unity command set_autotick --enable true` → `unity command run_tests --mode editor --async_tests true`
→ `unity command test_status`.

**Откат:** файлы новые; удалить класс и тест — мир не задет.
