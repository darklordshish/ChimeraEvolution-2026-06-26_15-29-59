## Шаг 1. Прибор: метрики в рантайм, а не в тест

**Почему первым.** S1 §6.2 и его план (шаг 3) заводят сторожа `DomeReliefTests` с метриками полос. Если
метрики останутся **внутри EditMode-теста**, их не увидят PlayMode-ворота: `Chimera.Tests.EditMode` и
`Chimera.Tests.PlayMode` — разные сборки (`Assets/_Chimera/Tests/EditMode/Chimera.Tests.EditMode.asmdef`,
`.../PlayMode/Chimera.Tests.PlayMode.asmdef`). Значит реализация обязана быть **рантайм-кодом**, а тесты —
только вызывать.

**Делаем.** `Assets/_Chimera/Scripts/Forest/Generation/ForestLandscapeMetrics.cs` (новый, рантайм) —
одна реализация M1–M5 **по формулам S1 §3.3–3.6**, без своей математики:

- `Slope(...)` — `atan‖∇h‖` при двух ε, p50/p95/p99, доли >22/>35, отдельно «проходимое» и «стена»;
- `LongEnergy(...)` — `Var(box250(H0)) / Var(H0)` (S1 §6.2);
- `MesoCoverage(...)` — окно 300×300, `p90−p10 ≥ 12` (S1 §6.2);
- `Landforms(...)` — `H/D`, `H/W`, `blend/H`, `D/W` по типам (S1 §3.5), **из поля**, не из `DomeRelief.State`;
- `SeamJump(...)` / `MinCurvatureRadius(...)` — `|Δslope|` на 1 м и радиус (S1 §3.6).

Если S1 уже написал это внутри `DomeReliefTests` — **переносим**, а не пишем второй раз. Владелец
формул — S1; владелец класса-носителя — пакет (сводится при приёмке пакета).

**Тест.** `Assets/_Chimera/Tests/EditMode/Forest/Worldgen/ForestLandscapeMetricsTests.cs` (новый) —
проверяет **инструмент на синтетике**, а не мир:

| поле | ожидание |
|---|---|
| плоскость | p50 = p95 = p99 = 0, `E_λ = 0`, мезо 0 |
| один холм с известным `H/D` | `H/D` совпадает ±2 %, `|∇h|max = 3H/D` (S1 §3.3) |
| синус `λ = 500 м` | `E_λ ≈ 1` |
| белый шум | `E_λ ≈ 0` |
| гребёнка `λ = 40 м` | излом растёт, `E_λ ≈ 0` |
| синтетическая гряда `W=35, H=4.2` | ≤ 19.8°, а не 70° (эталон S1 плана, шаг 4) |

**Ворота.** Все шесть строк зелёные. **Не делать:** не гонять на `ForestBuilder`, не подбирать пороги под
текущий мир, не заводить второй класс метрик.

**Команда:** `unity command set_autotick --enable true` → `unity command run_tests --mode editor --async_tests true`
→ `unity command test_status`.

**Откат:** файлы новые; удалить класс и тест — мир не задет.

## Шаг 3. Карта, горизонтали, разрез

**Делаем.** `ForestMapBuilder` читает `WorldHeightField` (`ForestMapBuilder.cs:47`) — старое поле, не
купол (`Docs/les/LEVEL-DESIGN-I-GENERACIYA.md:24`). Новый `ForestMapPainter` (рантайм/Editor):

- цвет по высоте + **изолинии 1 м** + маркеры: арены, коридоры, поды, логова, вода, `Entry`, `LabDoor`;
- профиль разреза `Entry → LabDoor` (как S2 §5.1) и ось через две самые высокие формы + гряду —

**Ворота.** Цвет клетки = `SampleGround` в той же точке; изолиния 1 м не самопересекается; на карте видны
все арены, коридоры, вода и логова, которые есть в мире (сверка с `builder.Clearings/Corridors/Lairs`).
**Не делать:** не удалять `КАРТА_ЛЕСА` и `ForestMapBuilder` — снять с роли ворот, оставить историей.

**Откат:** painter не подключён к игре; удаляется без следа.

## Шаг 8. Приёмка S1: поле

**Делаем.** Прогон шагов 1–7 на поставке S1. Новых метрик нет.

**Принимаем, если:** G1–G3 зелёные на профиле сцены и на `p10` 20 сидов; кадры Р1 (разрез) и Р2
(горизонтали) читаются; G7 пройден. Плюс **подтверждён или опровергнут** расчёт S1 §0.2: гряда 60–77°.
Подтвердилась — S1 принимается **с условием** правки профиля гряды (S1 §3.3, капсула вместо `max`), а не
порога.

**Блокер, а не долг:** если `H/D` S1 §3.5 (0.06–0.12) и S2 §1.2 (0.05 / 0.14) не сведены (развилка §9.1
спеки), `G2` нельзя ни зазеленить, ни списать: S5 пишет «не сведено» и останавливает приёмку S1.

**Не принимаем:** «стало больше перепада» — перепад не метрика. S4 предъявляется теми же метриками
«до/после»; своих ворот S5 для эрозии не заводит.

## Шаг 9. Приёмка S2: композиция

**Принимаем, если:** ориентир виден с ≥80 % точек маршрута в 80–150 м; арены и коридоры читаются **без**

равно не понравиться в игре — это записывается прямо, а не прячется.
