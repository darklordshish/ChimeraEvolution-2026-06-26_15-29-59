# План: B0.3 — генерация плана интерьера бункера

**Статус:** план к действующей спеке, код не начат. **Дата:** 2026-10-26.
**Спека:** [`2026-10-25-forest-lab-entrances-damage.md`](../specs/2026-10-25-forest-lab-entrances-damage.md) §6, §9 (B0.3).
**Родители:** B0.2a/b/c (входы, рампа, разрушения), B1.1b (овраги) — не переписываются.
**Цель:** генерировать **валидные варианты внутреннего плана** поверх уже принятой оболочки B0.2; фиксированный
план B0.1 остаётся одним из вариантов и продолжает работать. Повреждения B0.2c накладываются на
сгенерированный план, а не на хардкод координат.

---

**Статус 26.10:** Task 1 и Task 2 выполнены: `fixed`/`mirror`/`deep-wings`, геометрия, повреждения, сцена B0.3, тесты. `deep-wings` — глубина 19 (21 не влезает в пятно 46×36 с ареной 8) и мебель у дальних краёв крыльев. Дальше Task 3/4; B1.1b (овраги) не блокирует.

## 0. Что НЕ делаем

- не меняем входы, рампу, скалу, ясень, овраги, климат, B1;
- не вводим зверей, `LairSite`, спавнер внутри лаборатории;
- не делаем runtime-разрушение, кровь, тела, новых монстров;
- не режем 46×36 произвольными прямоугольниками;
- не трогаем A/C (`ForestSandbox`, Ø2000/1337) и старый лабиринт;
- не обещаем «любой план»: только проверенные шаблоны/модули с валидацией и запасным фиксированным планом.

---

## 1. Стратегия

Сначала **вытащить текущий фиксированный план в данные**, не меняя картинку. Это даёт:
- один источник геометрии (комнаты, двери, обход, функции);
- возможность прогнать старые тесты/кадры и убедиться, что B0.2 не поехал;
- точку, в которую подключается генератор.

Только после этого включать варианты. Генератор не должен быть «умным»: два-три проверенных
шаблона + зеркалирование + модули глубины крыльев. Всё, что не прошло валидацию, откатывается
на фиксированный план с записью причины.

## 2. Данные

### 2.1. `LabPlan` (новый файл `Forest/Facility/LabPlan.cs`)

```csharp
public enum LabFunction { Hall, Arena, Surgery, Cells, Rest, Lobby }

public struct LabRoom
{
    public string id;          // "hall", "arena", "surgery", "cells", "rest", "lobby"
    public LabFunction function;
    public float x, z;         // центр в локальном кадре лаборатории
    public float width, depth; // чистые габариты
    public float height;
}

public struct LabDoor
{
    public string from, to;    // id комнат
    public float x, z;         // центр проёма в локальном кадре
    public float width, height;
    public bool alongX;        // стена идёт по X
}

public sealed class LabPlan
{
    public int version;
    public string template;    // "fixed", "mirror", "deep-wings"
    public List<LabRoom> rooms;
    public List<LabDoor> doors;
    public float footprintX, footprintZ; // 46 × 36
}
```

### 2.2. `LabPlanRules` (`Forest/Facility/LabPlanRules.cs`)

Валидация возвращает список строк, а не бросает исключение:
- footprint 46×36; комнаты не выходят за пятно;
- нет пересечений комнат (кроме общих стен/дверей);
- зал 14×14, обход 2.5 по периметру;
- четыре функции: арена, хирургия, клетки, отдых;
- двери ≥ 4.0 × 4.0 (B0.2), вход ≥ 4.2;
- граф связей: `lobby → hall`, `hall → arena/surgery/cells/rest`;
- путь к каждой функции не идёт через клетки и не требует прохода через арену;
- `LabDoor` и `LabAtrium` — те же адреса B1;
- крыша над всем пятном, центральной колонны нет.

### 2.3. `LabPlanFixed` (`Forest/Facility/LabPlanFixed.cs`)

Текущий B0.2-план, перенесённый один-в-один:
- арена 46×8.5 север;
- хирургия 13.5×19 запад;
- клетки 13.5×19 восток;
- отдых 46×8.5 юг (входная полоса восточнее перегородки);
- зал 14×14 + обход 2.5;
- двери 4.0×4.0, портал 4.2.
Числа берутся из `DomeLabComplex` один раз; после переноса старые константы не должны оставаться
вторым источником.

## 3. Генератор

### 3.1. `LabPlanGenerator` (`Forest/Facility/LabPlanGenerator.cs`)

Вход: `seed`, `planVersion`, `LabEntrance`, `LabStyle`.
Выход: `LabPlan` + `string note` + `bool fallback`.

Порядок:
1. выбрать шаблон: `fixed` / `mirror` / `deep-wings` (веса/сид);
2. применить зеркалирование хирургии/клеток;
3. выбрать модуль глубины крыльев (например, 17/19/21 м) из проверенных;
4. проверить `LabPlanRules`;
5. при провале — следующий вариант; после лимита — `LabPlanFixed`, `fallback = true`, note в лог.

**Случайность независимая:** отдельные соли для шаблона, зеркала, глубины и мебели; изменение мебели
не меняет двери. Сид мира + `planVersion` — единственный вход.

### 3.2. Что варьируется

- зеркало: хирургия ↔ клетки;
- глубина крыльев: 17/19/21 м в допустимых пределах;
- раскладка мебели внутри комнат (не геометрия дверей);
- место события повреждений (B0.2c) — отдельная последовательность.

Не варьируются: пятно, зал, обход, двери, вход, `LabDoor`, `LabAtrium`, высоты, крыша.

## 4. Как это встраивается в код

### 4.1. `DomeLabComplex`

- `Build(..., LabPlan plan = null)`: если `plan == null` — `LabPlanFixed.Create()`.
- Стены, двери, комнаты, мебель и свет читают `LabRoom`/`LabDoor`, а не литералы.
- `Result.planTemplate`, `Result.planVersion`, `Result.planFallback` — для лога/тестов.
- Существующие публичные константы (`HalfWidth`, `HalfDepth`, `HallHalf`, `DoorWidth`, `DoorHeight`,
  `PortalWidth`, `RoomHeight`, `HallHeight`) остаются, но план обязан с ними сходиться; расхождение — ошибка.

### 4.2. `DomeWorld` / `ForestBuilder`

- `ForestBuilder.buildLabPlan` (bool, default **false**; B0.2 остаётся фиксированным).
- `ForestBuilder.labPlanVersion` (int, default 1).
- `DomeWorld.Build(..., bool buildLabPlan = false)`; при true — `LabPlanGenerator.Generate`.
- `DomeWorld.LabPlan` — факт мира; `Clear` обнуляет.
- В лог: `plan=fixed|mirror|deep-wings`, `version`, `fallback`, seed.
- Сцена B0.3: `ForestFragment` с `buildLabPlan = true`, `buildRavines = true`, `buildAsh = true`,
  `labEntrance = Underground`, сид 9.

### 4.3. `DomeLabDamage`

- Принимает `LabPlan`; выбирает отсек/стекло/стол по id комнат и дверей, а не по литералам.
- Имена объектов остаются контрактом (`SurgeryGlass`, `CellBar`, `SurgeryTableTop`, `LabLight_*`).
- Если план не содержит нужного объекта — повреждение пропускается с записью, не NRE.
- Событие: один отсек → служебный проход → зал → стекло хирургии; двери не блокируются.

## 6. Проверки

### EditMode

- `FixedPlan_IsValid` — фиксированный план проходит правила.
- `Generator_SameSeed_IsReproducible` — один сид/версия → один план.
- `Generator_DifferentSeed_ChangesTemplate` — набор сидов показывает варианты.
- `Generator_Fallback_WhenRulesFail` — подсунуть заведомо плохой модуль, получить `fixed` + note.
- `Plan_DoorsAndHall_MatchB02` — 4.0/4.2, зал 14, обход 2.5.

### PlayMode

- `GeneratedPlan_Builds_OnThreeSeeds` — `LabComplex != null`, `LabDoor` есть, `Chunks == 12`.
- `GeneratedPlan_AllFunctionsReachable` — NavMesh-путь `LabDoor → LabAtrium → arena/surgery/cells/rest`.
- `GeneratedPlan_Damage_IsReproducible` — подпись повреждений.
- `GeneratedPlan_Clear_RemovesEverything` — после `Clear` нет плана/повреждений/ламп.
- `A_OldLab_WhenComplexOff` — без изменений.
- `B02_FixedPlan_StillGreen` — старые тесты B0.2 не правятся.

### Кадры

- top и 3/4 для двух вариантов;
- хирургия/клетки после повреждений;
- сравнение fixed vs mirror vs deep-wings на одном сиде;
- вход/рампа не меняются.

## 7. Риски

1. **Хардкод имён в `DomeLabDamage` и тестах.** Сначала контракт имён, потом генератор; иначе
   повреждения молча пропадут.
2. **Дверь 4.0 и стены 0.5.** Любой модуль обязан сохранять проём; `DomePass`/NavMesh проверить.
3. **Зал 14×14 + обход 2.5** — не варьировать; это уже принятая форма.
4. **Печь NavMesh после плана** — план до `BuildNavMesh`, иначе пути старые.
5. **`Clear` и статические кэши** — план/повреждения/лампы не должны переживать снос.
6. **A/C** — генератор только за флагом B0.3; старый лабиринт не трогать.
7. **Не превратить B0.3 в B1.** Места/связи/ареалы — после.
