## Шаг 1. Контракт: `worldVersion`, полосы, `lambdaMin` (1 день)

**Цель:** ввести версию контракта и параметры полос, **не меняя ни одной высоты**.

**Действия.**
- `ForestBuilder`: поле `worldVersion` (default 1), писать в `ownedConfig.worldVersion` (не `cfg.version`); A/C-сцены — 1, `ForestPavilion` — 1 (переключение позже, в S3).
- `DomeGenConfigSO`: поля полос (`macro/meso/micro`: λ, P, октавы, warp-доля, ridged-флаг) с дефолтами, воспроизводящими v1; старые `baseFrequency/amplitude/warpStrength` остаются для v1.
- `SamplingContract`: добавить `meshStep` и `lambdaMin` (минимальная λ октавы) как контрактные величины; `From` считает их из конфига и `terrainQuads`.
- `DomeGenRules`: проверки новых полей (λ>0, P≥0, октавы в диапазоне, `P/λ ≤ 0.12` для v2).
- `GenTrace`: слой `height` с полосами и версией.

**Проверка.** `DomeHeightTests` (5 методов), `SamplingContractTests.From_NamesMeshSlopeRouteAndNavResolutions`, `ForestBaselineTests` — зелёные; хэши шага 0 не сдвинулись; `ForestPavilion` не изменился.

**Коммит.** `S1: worldVersion и контракт поля`.

## Шаг 2. `H0` v2: три полосы (2 дня)

**Цель:** реализовать `H0` как сумму трёх полос, сохранив v1 бит-в-бит.

**Действия.**
- В `DomeHeightField` — две ветки: `v1` (текущая формула) и `v2` (три полосы). Выбор — по `worldVersion`; `SampleRaw` остаётся единственным скалярным источником, `DomeHeightJob` вызывает его же.
- v2: `N_b` — zero-mean value-noise/fBm; warp — доля λ (`A_w ≤0.12·λ_w` для 1 октавы, `≤0.06·λ_w` для 2) и `|∇w| ≤0.8`; ridged — только мезо и только под маской; постоянный сдвиг `−0.12(1−m)` не переносится.
- Нормировка — константа, не `max` по сетке.
- `SampleGridHash` — отдельный для v2; `WorldVersion_ParticipatesInHash` (новый метод) подтверждает соль `worldVersion`; `cfg.version` не трогаем.
- Стенд: `worldVersion=2` только в тесте/отчёте, не в сцене.

**Проверка.** `DomeHeightTests` (v1-методы), `Heights_WithinBandEnvelope` (v2), `DomeChunkTests.NeighbourChunks_MeetSeamlessly`, `DomeHeightJobTests` (скаляр = джоба), `WorldGenDeterminismTests`, `Warp_DoesNotFold`; v1-хэши шага 0 совпадают; на v2 нет октавы с λ < 20.8 м.

**Коммит.** `S1: H0 тремя полосами за v2`.

**Риск.** Джоба и скаляр разойдутся на warp/нормировке — ловится только `DomeHeightJobTests`; без него шов чанка «сойдётся», а джоба будет рисовать другое.

## Шаг 4. Алгебра форм (2 дня)

**Цель:** отделить математику формы от размещения.

**Действия.**
- Модуль форм (имя рабочее — `DomeForm`): знак `s=±1`, `H`, носитель (диск/капсула/эллипс/полилиния), профиль `φ`, маска, подошва.
- Профили: `S(1−u)` для холма/чаши/оврага; капсула для гряды; плато `1−S` для террасы; `smax` с `k=0.2` для подошвы.
- Никакого размещения: формы принимают координаты/маски снаружи. Размещение — S2.
- Тесты: C¹ на швах, H/D, кривизна, подошва, баланс P/N — на синтетических формах, без карты.

**Проверка.** `Forms_C1_AtSeams`, `Curvature_Radius_AtLeast5m`, `Hills_Aspect_AtMostTwelvePercent`, `Ridges_Aspect_AtMostTwelvePercent`, `Ravines_Aspect_AtMostTwentyFivePercent`, `Soles_AreFlat_AndCounted`, `PositiveNegative_Balance_WithinTwentyPercent` — зелёные; синтетическая гряда W=35 м, L=100 м, H=4.2 м даёт ≤ 19.8°, а не 70°.

**Коммит.** `S1: алгебра форм и профили`.

## Шаг 5. P5-lite: `Apply` на формах (1.5 дня)

**Цель:** заменить **оператор** `DomeRelief.Apply` на сумму форм; раскладку не трогать — она S2.

**Действия.**
- `DomeRelief.Apply` **в v2** принимает список форм (`Lift/Carve` + маска) и складывает; гряда — капсула, не `max`; H/D ≤ 0.12; v1 не трогать.
- `DomeRelief.Build` (раскладка) **не S1**: S2 заменит его на `DomeComposition`; S1 даёт только `Apply` и профили. Для тестов S1 — синтетический список форм.
- `ReliefHills` для v1 не меняется; v2 считает P-формы из входного списка.
- `WorldFingerprint`: смешать `worldVersion` и список форм (центр, R, H, знак, ось).
- `ForestPavilion` остаётся на v1 и старом P5-lite; формы v2 проверяются на `worldVersion=2` в тестовой сборке, не в сцене.

**Проверка.** `ForestPavilionTests.Relief_IsPresent` на v1 не изменился; новые `ReliefV2_...` (H/D, уклон, C¹) на `worldVersion=2` и синтетическом списке; `Fingerprint_IncludesRelief`; A/C **высотные** хэши шага 0 целы.

**Коммит.** `S1: оператор форм для P5-lite`.

## Что не делать в плане

- Не переключать `ForestPavilion`/`ForestFragment`/`ForestSandbox` на v2 — это S3.
- Не размещать POI и не двигать вход/станцию/логова — S2.
- Не менять `DomeWorld.SampleGround` и pad — S3.
- Не делать эрозию и не тащить её в рантайм — S4.
- Не трогать NavMesh, флору, коллайдеры, камеру — S3.
- Не «улучшать» A/C ради красоты: A/C — эталон, а не поле экспериментов.
- Не вводить числа без происхождения: каждое число шага — из §3 спеки или из замера шага 0/3.

## Риски плана

1. **Джоба ≠ скаляр.** `DomeHeightJob` может разойтись с `SampleRaw` на warp/нормировке; шов чанка это не поймает. Лечение — parity-тест на каждом шаге 2–6.
2. **Базлайн поплывёт от «безобидной» правки.** `DomeHeightField` общий для A/C; любая правка v1-ветки меняет все сцены. Лечение — v1 не трогать, только добавлять ветку.
3. **Маски съедят формы.** `w_m ≥ 4H` делает форму высотой 15 м с переходом 60 м; у POI места может не остаться. Лечение — снижать H у POI или двигать форму (S2), а не ослаблять маску.
4. **20 сидов дадут выброс.** Один сид из 20 может дать ровное поле или стену; это не повод менять порог — сначала разбор trace, потом решение.
