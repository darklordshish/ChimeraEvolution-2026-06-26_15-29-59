## 2. Ответы

1. **Единица конечности — диаметр конца шасси. Да.** Поперёк (X/Y) конец задаётся в диаметрах. **Длина — по вашему
   наблюдению из §3 таблицы:** у ОПОРНОЙ конечности конец дотягивает билдер — от гнезда до земли, это калибр шасси
   (высота запястья волка 0.50, ежа 0.09 — разница в десять раз, и она принадлежит носителю, не донору). У неопорной
   (руки человека) — длина в диаметрах, ваши 1.6–2 годятся. Какие конечности опорные — решает ШАССИ (волк, лось, ёж —
   обе пары; человек — ноги; змея — ни одной), это запись вида, наша. Позже это станет тегом `Опора` из алгебры тегов
   (спека §7–§8).
2. **Иглы — по игле, ваши четыре числа.** Доля длины спины, угол от хребта, длина в долях длины спины, завал в
   градусах. Параметры поля игл — потом, если упрёмся в размер файла. **Змея — кадр Шкуры на каждом звене**, как вы
   предложили: иглы едут с цепью.
3. **Рога — парное гнездо**, как уши и глаза: у каждого шасси две точки, расстояние между ними — калибр носителя
   (ширина головы). У волка — у основания ушей, у ежа и человека — по бокам темени. Одиночный рог, если понадобится,
   решим тогда.
4. **Наконечник — ребёнок гнезда `Хвост`**: есть аугмент хвоста — на его конце; нет — на конце хвоста шасси, а у кого
   хвоста нет (человек) — на корне. Ваше предложение, принято.
5. **Метры в вашей таблице законны.** Закон «в данных донора нет метров» — про АУГМЕНТЫ. Гнездо — калибр шасси, его
   числа в метрах тела. Кость-хозяина (П7: гнездо живёт на кости, чтобы его везла анимация) и перевод в кадр кости
   берём на себя при чтении.
6. **Человек: морда волка в 1.8 раза меньше волчьей** — верно по закону, смотрим глазом на оборотне, когда билдер будет
   готов.

## 3. Формат

Один файл на вид — `handoff/<вид>-places-layout.json`. Места из `head-layout` (`places`) переезжают сюда; морда, зубы и
`senses` пока остаются в `head-layout` — они аугменты, их переведём вторым шагом.

```json
{
  "species": "Волк",
  "places": [
    { "name": "Пасть", "host": "голова", "pos": [0, 1.08, 0.86], "dir": [0, -0.37, 0.93], "unit": 0.27 },
    { "name": "Рога",  "host": "голова", "pos": [0.07, 1.30, 0.86], "dir": [0, 0.8, -0.6], "unit": 0.27, "mirror": true },
    { "name": "Руки",  "host": "предплечье", "pos": [0.09, 0.50, 0.42], "dir": [0, -1, 0], "unit": 0.104, "mirror": true },
    { "name": "Шкура", "host": "хребет", "surface": { "z0": -0.60, "z1": 0.42 }, "unit": 1.02 },
    { "name": "Хвост", "host": "крестец", "pos": [0, 0.93, -0.60], "dir": [0, -0.5, -0.87], "unit": 0.19 }
  ]
}
```

- `pos`, `dir` — метры и направление в системе тела (Y от земли, Z к носу, X вправо; левую сторону даёт `mirror`);
- `host` — узел графа этого вида, на котором гнездо живёт; у змеи для цепи — `"звено:N"` (N от головы), у мест без
  узла — ближайший узел по смыслу (ноги змеи — звено у хвоста, как у вас в таблице);
- `unit` — единица гнезда в метрах (ваша строка «единица»);
- `proposed: true` — ваш знак ✎ (гнездо у вида, у которого места нет); детектор такие считает, но не ругает;
- **все места словаря у всех пяти видов** — `Graph.Check` будет проверять тотальность (И6).

Пока билдер не читает файл, он лежит молча — перекладывайте по готовности, одной поставкой на все пять видов.
