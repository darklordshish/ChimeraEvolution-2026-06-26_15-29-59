# ТЗ модельной линии: что механики ждут получить и как это принимается

- **Дата:** 2026-09-17 · **От:** линия механик · **Кому:** модельная линия
- **Читать после** [`ONBOARDING-модельной-линии.md`](ONBOARDING-модельной-линии.md)
- **Действующий метод:** [`SPEC-konstruktor-formy.md`](SPEC-konstruktor-formy.md) (10.09) — тело полем,
  детали блоками. Требования к блокам и бюджет — [`SPEC-model-contract.md`](SPEC-model-contract.md) §7.4.

Это ТЗ на ПОСТАВКУ: форматы, инварианты, порядок, приёмка. Решения о форме («сколько и какой формы»)
остаются вашими — здесь сказано, **в каком виде** они попадают в игру и **чем проверяются**.

---

## 1. Три поставки, в этом порядке

| # | что | формат | блокирует |
|---|---|---|---|
| 1 | **`skeletonHides` по человеку, лосю, ежу, змее** | список имён мест (в файле графа или письмом) | всё остальное |
| 2 | **силуэтный граф вида** | JSON, формат §3 | кадр, бюджет, смешение |
| 3 | **ригблоки + раскладка деталей** | FBX + таблица долей | детали силуэта |

Почему `skeletonHides` первым: сейчас у четверых видов кости и места рисуют тело ОДНОВРЕМЕННО (лось —
9 оболочек костей против 84 примитивов мест). Пока это так, любой кадр — кадр двух геометрий, и принять
по нему нельзя ни силуэт, ни блок, ни смешение.

**Вывести список автоматически нельзя, и это не лень:** челюсть принадлежит слоту «Пасть», но подавить
место «Пасть» значит потерять зубы. Что гасит поле, а что остаётся деталью — решение формы.

## 2. Что такое узел силуэтного графа

**Узел — это `Bone` с жирными радиусами и обязательным `socket`.** Второго формата в проекте не
заводится: узел силуэта — не новая сущность, а та же кость, только их ~20, а не 130.

Что узел несёт (поля `Bone`, все в метрах или долях):

| поле | смысл | обязательно |
|---|---|---|
| `name` | имя-адрес узла, уникально | да |
| `parent` | родитель по графу; пусто — КОРЕНЬ, он один | да, кроме корня |
| `socket` | **место, объём которого этот узел даёт** — по нему режется меш и работает химеризация | да |
| `origin` | точка старта КОРНЯ, метры от земли | у корня |
| `attach` | где на родителе начинается узел: доля его длины (1 = конец, 0.5 = середина) | да |
| `freeOrigin` | родитель даёт только родство и поворот, начало своё (`origin` в кадре родителя) | по месту |
| `length` | длина узла, м | да |
| `dir` | углы поворота относительно родителя; наследуются вниз по цепи | да |
| `r0`, `r1` | радиусы у начала и конца, м. **Это ЖИР, а не кость**: разные радиусы дают веретено | да |
| `section` | сечение поперёк: 1 = круг, 0.5 = вдвое уже (грудь зверя почти плоская) | по месту |
| `depth` | сечение вдоль взгляда: для плоского (ухо, лопасть рога) | по месту |
| `blend` | насколько узел сливается с соседями; 0 = взять общий по виду | по месту |
| `chain` | сегментов, если узел составной (позвоночник, хвост) | по месту |
| `mirrorX` | пара зеркально по X: одна запись даёт обе стороны | по месту |

**Чего в узле НЕТ и не будет:** вершин, полигонов, материалов, UV. Узел описывает объём, а поверхность
строит игра.

## 3. Формат файла поставки

JSON, кладётся в `Docs/models/handoff/<вид>-graph.json`:

```json
{
  "species": "Волк",
  "hides": ["хребет", "шея", "голова", "Ноги", "Руки", "Шкура"],
  "nodes": [
    {
      "name": "грудь", "parent": "", "socket": "хребет",
      "origin": { "x": 0.0, "y": 0.62, "z": 0.10 },
      "attach": 1.0, "freeOrigin": false,
      "length": 0.34, "dir": { "x": 0, "y": 0, "z": 0 },
      "r0": 0.16, "r1": 0.18, "section": 0.72, "depth": 1.0,
      "blend": 0.09, "chain": 0, "mirrorX": false, "layer": 0
    }
  ]
}
```

**Образец с реальными числами уже лежит** — `Docs/models/handoff/volk-graph-current.json`: это выгрузка
нынешних костей волка ровно в этом формате (`Graph.Export`). Берите как пример полей, **но не как
пример графа**: в нём 130 узлов и 7 корней, и проверку он не проходит.

## 4. Инварианты поставки — их проверяет машина

`Graph.Check` печатает ВСЕ нарушения разом:

- **граф связен, корень один.** Нынешний скелет волка распадается на 7 кусков — так нельзя;
- **узлов ~20**, мягкий потолок 40. Больше — это анатомия, а не силуэт;
- **у каждого узла есть `socket`** — иначе меш не нарезать по слотам и химеризация не сработает;
- **радиусы больше нуля**, длина больше нуля;
- **имена уникальны**, родитель существует;
- **гасимое место существует у вида.**

Проверка ничего не меняет. Приёмка (`Graph.Import`) пишет в данные вида ТОЛЬКО при чистой проверке.

## 5. Бюджет — и почему он сейчас открытый вопрос

Контракт §7.4 называет 600–1 500 треугольников на зверя. **Замер 17.09 говорит, что одним полем в него
не попасть:**

| клетка поля | треугольников у волка | силуэт |
|---|---|---|
| ×0,5 | 225 340 | мелкая рябь |
| **сейчас** | **56 492** | на спине мусор из несплавленных бугров |
| ×4 | 4 760 | **чище, чем сейчас** |
| ×10 | 2 072 | разваливается: ноги отрываются, голова сплавляется |

Отсюда развилка, которую решает геймдизайнер: **децимация изоповерхности** до бюджета (ваш же метод из
письма 10.09) или **поднять потолок до ~5 000**. Пока решения нет, **делайте граф «жирным» и не думайте
о полигонах**: плотность сетки — наша ручка (`skinCell`), не ваша.

Заодно замер: `skinBlend` ×2 делает волка в полтора раза шире (0.46 → 0.68 м) — слияние раздувает тушу,
и «юбка» между ногой и грудью родом отсюда.

## 6. Ригблоки и раскладка

Требования к блоку — контракт §7.4, коротко: габарит ровно 1×1×1 с центром в нуле, канонический кадр
(+Z вдоль тела, +Y наружу), имя объекта = имя блока, один FBX на библиотеку, экспорт
`Scale 1.0, −Z Forward, Y Up, Apply Scalings: FBX All`, без своих материалов и UV, шов перекрывать.

Каталог уже создан и пуст: `Assets/_Chimera/Resources/Формы.asset`. Механика приёма готова — деталь
называет форму строкой (`OrganPart.block`), нет блока в каталоге — рисуется примитив, а промах имени
копится в `MorphBuilder.MissingBlocks`.

**Раскладка** — таблица «место → куски (форма, масштаб, смещение, поворот)» в ДОЛЯХ места. Числа ваши,
запись наша: пришлите таблицей, мы внесём в данные видов.

## 7. Как проходит приёмка

```
вы кладёте файл → Graph.Check (инварианты) → Graph.Import (в данные вида)
   → chimera-map (карта тел: габариты, стыки, химерные сборки)
   → кадр на полигоне: вид в профиль, ряд пяти видов, тройка «шасси · химера · донор»
   → ответ письмом: числа и картинка
```

Всё это делает линия механик в тот же день. От вас нужен только файл.

**Что мы проверяем на приёмке, кроме ваших чисел:** топология носителя не изменилась, корень не
смешивается, локальность (графт двигает места под собой, а не всю тушу), стыки без щелей и нахлёстов,
бюджет треугольников.

## 8. Порядок на первые дни

1. `skeletonHides` по четырём видам — письмом или прямо в файле графа;
2. силуэтный граф **волка** (он первый: по нему есть эталонный обвод с фотографии и промеры);
3. кадр от нас → правки → повтор, пока силуэт не станет волчьим;
4. три блока + раскладка деталей волка;
5. по результату — остальные четыре вида.

**Не начинайте с пяти видов сразу.** Один вид, доведённый до годного силуэта, стоит дороже пяти
начатых: ровно этим закончились три предыдущих метода.
