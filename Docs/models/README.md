# Docs/models — рабочая папка модельной линии

Здесь лежит всё, что нужно, чтобы сделать модель существа и отдать её в игру **готовой к
подключению**. Сами модели живут не здесь: генераторы — в `Tools/Blender/`, готовые FBX — в
`Assets/_Chimera/Models/`.

## Порядок чтения — с нуля

1. **`SPEC-model-contract.md`** — контракт модели с кодом. Что за игра, зачем модели режутся по
   слотам, что игра делает с моделью, оси Blender→Unity. **Читать целиком один раз**, дальше
   возвращаться по оглавлению.
2. **`Assets/_Chimera/Models/README.md`** — что уже сделано: части, кости, материалы, пределы
   углов, грабли Blender. Формат раздела на вид задан там же.
3. **`species/<вид>.md`** — ТЗ на конкретный вид, если оно есть. Бланк — `species/_template.md`.

## Раскладка

```
Docs/models/
  README.md                 этот файл: процесс и навигация
  SPEC-model-contract.md    ГЛАВНОЕ: контракт данных и механик
  species/
    _template.md            бланк ТЗ на вид
    <вид>.md                ТЗ: что нужно, зачем, с какими числами
  handoff/
    <вид>-<дата>.md         сдача-приёмка: что отдано, что принято, что осталось
```

## Как идёт работа

```
ТЗ на вид            линия механик пишет species/<вид>.md: слоты, габариты, что должно читаться
   ↓
модель               модельная линия делает генератор в Tools/Blender/, кладёт FBX в Models/
   ↓
паспорт              раздел вида в Models/README.md: части, кости, материалы, углы, недоделки
   ↓
приёмка              handoff/<вид>-<дата>.md: сверка по чек-листу SPEC §9
   ↓
подключение          линия механик собирает префаб и данные вида (SpeciesSO)
```

**Модель в префабы не подключает модельная линия** — причина в SPEC §10, она не бюрократическая.

## Что делать, если данные и модель расходятся

Данные — источник правды (парадигма «данные-первыми»). Если модель рисует то, чего нет в
`SpeciesSO` (орган, слот, придаток), — правится модель либо, если фича настоящая, сначала заводятся
данные, и только потом форма.

Обратный случай — данные требуют формы, которой нет в модели, — это **пропажа**, и она видна только
глазами на скриншоте. Поэтому в паспорте вида есть раздел «известные недоделки»: честный список
дешевле, чем поиск причины через три итерации.

## Открытые вопросы

Решаются с пользователем, не решаются агентами в одиночку:

- **Основной путь формы.** Сейчас процедурный морф и Blender-модели живут параллельно (SPEC §7).
  Переход на модели как основной путь — не решён.
- **Мэппинг слотов между шасси** — не проработан, ждёт систему смены шасси (post-MVP).
- **Слияние формы двух органов на одном месте** (родной + химерный) — будущая фича.
