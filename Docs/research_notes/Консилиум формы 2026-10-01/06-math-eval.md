## 0. Коротко

1. **У нашей задачи есть факт, который упрощает всё и который пока не использован:** шасси у тела НЕ МЕНЯЕТСЯ НИКОГДА.
   Ступень 3 возможна только на родном шасси (решение 2), стойка за шасси (решение 8). Значит, тип тела —
   **несвязная сумма по шасси** `Body = Σ (c : Chassis). Body_c`, и ни одна операция игры не переходит между слагаемыми.
   Любой вариант, который тратит сложность на «общее пространство всех видов» (В4) или «любой граф в любой граф» (В1),
   платит за связность, которой правила игры пользоваться запрещают.
2. **В спеке двух слоёв есть дыра в композиции.** Порядок §6.1 — «3. локальный, 4. глобальный». Но глобальный слой
   §4.2 — `zipWith lerp` двух деревьев ОДНОЙ ФОРМЫ, а локальный (`Replace`) форму дерева меняет. После подстановки
   цепи `zipWith` с парным телом шасси не определён на заменённых поддеревьях. Определённый порядок — обратный:
   `body = local ∘ global`, глобальный действует на неизменной форме шасси, локальный подставляет поверх. Это важно для
   В1 и В2 и снимается само собой в В3.
3. **В3 — единственный вариант, где оба слоя — значения ОДНОГО типа** (точка в произведении симплексов весов), и
   композиция слоёв — это просто приоритет координат, без особых случаев. Но в описании `05` у В3 две неточности,
   и обе в его пользу и против него:
   - *в его пользу:* 140 региональных форм-ключей не нужны. При масках-разбиении единицы хватает **20 целых целей**
     (по 4 на шасси) — регион вырезается маской в рантайме ([L] §7.3: локальный и целый базис «покрывают одно и то
     же пространство»). Контент В3 — 5 мешей + 20 целей, а не 5 + 140;
   - *против него:* линейная смесь вершин НЕ живёт на SO(3). Это урок вашей же спеки «тело как расслоение» (11.09):
     `Part` — произведение пространств разной структуры. Пальцеходящая нога или голова «взглядом» — большие повороты;
     их линейная смесь при `g₁` сплющивает форму ([A]). Лечится расслоением: **скелет — в группе Ли (как уже
     записано в спеке §4.3), меш — остаток в кадрах костей**, потом скиннинг. Это ровно устройство SMPL [P].
4. **Частичность в В3 конечна и перечислима:** это клетки «шасси × слот», у которых в топологии шасси нет региона
   (руки у змеи, хвост у человека). Их ~3 из 120 — закрываются вставкой части по кольцу (механизм В2) или ригблоком.
5. **Рекомендация: В6 = В3 на расслоении + В2 как запасной механизм для отсутствующих регионов.** Ранг остальных:
   В2 > В4 > В1 > В5. Таблица — §7.

## 1. Что у нас уже есть: алгебра на 01.10

Чтобы оценивать варианты, надо записать нынешнее. По коду:

```haskell
data Tree a = Node a [Tree a]                     -- Tree.cs: Map = fmap, Fold = cata, Scan = наследуемый атрибут
data BodyNode = BodyNode { bone :: Bone, nests :: [Nest], graft :: Maybe Species }   -- BodyTree.cs

-- параметры узла — ПРОИЗВЕДЕНИЕ пространств разной структуры (спека 11.09):
type Bone ≈ (ℝ₊)ᵏ  ×  SO(3)  ×  ℝ³ (origin)  ×  Flags     -- длины/радиусы мультипликативны, повороты на SO(3)

local  :: Slot -> Tree BodyNode {-донор-} -> Tree BodyNode -> Tree BodyNode
local s d c = replace (isFocus s) (const (fmap (calibre κ c d) d)) c      -- ChainSwap.SwapChain, :106–:140
global :: Ступень -> Tree_σ Bone -> Tree_σ Bone -> Tree_σ Bone          -- спека §4.2–4.3, не сделано
global g base pair = zipWith (geodesicLerp g) base pair                  -- ln-смесь длин, slerp поворотов
eval   :: Tree BodyNode -> Mesh                                           -- BoneMesher: поле → изоповерхность → грани
```

Здесь `Tree_σ` — деревья фиксированной формы `σ` (это уже не рекурсивный тип, а **конечное произведение** `Bone^|σ|`:
у фиксированной формы дерево — просто вектор узлов). На нём `zipWith` тотален и `Bone^|σ|` — группа Ли, где
геодезическая смесь определена. На `Tree` произвольной формы `zipWith` частичен — определён только на парах одной
формы. **Это главный структурный факт для всей оценки.**

Три наблюдения о нынешнем, независимо от варианта:

1. **Локальный слой — действие произведения независимых слотов, но коммутативность не доказана.** Фокусы
   (`перед`, `зад`, `голова`, группа `Сердце`) — непересекающиеся поддеревья, и после решения 15 (грудь — лист на
   хребте) замены по разным слотам должны коммутировать. Код применяет их в фиксированном порядке таблицы `Map`
   (`ChainSwap.cs:73–78`), так что результат определён; но калибр и опорная точка (`Lowest`, около `:165`) читают
   *текущее* дерево носителя, и коммутативность — свойство, которое никто не сторожит. Дёшево проверить тестом:
   все 4! перестановок слотов дают тот же отпечаток.
2. **Калибр `κ` — это недостающий морфизм интерфейса.** Склейка двух частей по шву — это pushout
   `A ←i— S —j→ B`: существует, когда обе части имеют вложение ОДНОГО интерфейса `S`. У нас интерфейса как типа
   нет, и `κ(c, d)` по каждой паре *конструирует* `j` эвристикой — четыре правила (длина цепи; min(длина, стык);
   ширина головы; объём группы; комментарии `ChainSwap.cs:126–135`). Каждое правило — частный выбор морфизма там,
   где канонического нет. Отсюда «каждое правило найдено кадром после поломки» (`04` §4 п. 4): поиск морфизма
   перебором при отсутствии универсального свойства.
3. **Соответствие деревьев для глобального слоя — задача редакционного расстояния, и вы её уже решили метками.**
   Парное тело требует отображения дерева цели на дерево шасси. Общий случай — tree edit distance [B] (удаление,
   вставка, переименование узлов; для упорядоченных деревьев O(n³), для неупорядоченных NP-трудно). Infinigen делает
   его жадно сверху вниз: «рекурсивно сопоставляет детей, минимизируя разницу параметров крепления» [I, G.6.3].
   У вас разметка `limb`/`mark` (спека §4.1) превращает соответствие в **функцию, заданную метками**, — канонически,
   без оптимизации. Это правильный ход. Оставшаяся частичность — узлы без пары (хвост у человека, лопатка ежа) —
   ровно операции вставки/удаления, и вы закрываете их, как Infinigen, «ростом из нуля», с тем же известным
   побочным эффектом: Infinigen прямо пишет, что это даёт «маленькие рудиментарные руки или хвосты» на
   промежуточных существах, а при несовпадении типов частей — «дискретный переход на полпути» [I, G.6.3].

## 3. В1 — поле капсул + прореживание + парные тела на капсулах

**Структура.** `Body = Σ c. Tree Bone`, облик `eval : Tree Bone → Mesh`. Локальный — `replace ∘ fmap κ`,
глобальный — геодезическая смесь в `Bone^|σ_c|`. Прореживание (QEM) — постобработка `eval`, алгебру не трогает.

**Тотальность.**
- `eval` тотален: поле сваривает что угодно. Но тотальность куплена отсутствием интерфейса — любой набор капсул даёт
  *какую-то* поверхность. Это тотальность свободной конструкции: определено всё, гарантировано мало.
- `local` частичен двояко: нет фокуса у носителя → путь `GrowFromNest` (`ChainSwap.cs` после `:140`), нет цепи у
  донора → подставлять нечего. Обе ветки закрыты явно — хорошо.
- `global` частичен в построении парного тела: соответствие дерева цели дереву шасси — метками, а то, чего нет,
  растёт из нуля (рудименты [I]). Цель «змея» — граф из одного узла: соответствия цепей нет вовсе, поэтому спека
  §4.2 вводит третий объект — варана. **Вспомогательный объект, нужный только чтобы определить отображение, —
  верный признак, что естественного отображения нет.**

**Корректность по построению.**
- Связность оболочки — по построению поля, *если* капсулы перекрываются. На деле матрица держит 1122 нарушения
  «оторвано» (`brief.md` §2) — в основном цепь змеи и ригблоки, то есть то, что живёт ВНЕ поля.
- Шов — не тип, а `κ`-эвристика (§1 п. 2).
- Поверхность не инвариантна к малым правкам: решётку пришлось делать постоянной, иначе «правка крайнего узла
  переогранивала всё тело» (CLAUDE.md, `LatticePhaseTests`). `eval` не локален и не липшицев по параметрам
  в смысле картинки: малое изменение узла — заметная перестройка граней.

**Композиция слоёв — здесь главная находка.** Спека §6.1 задаёт порядок: локальный (3), потом глобальный (4).
Но:

```haskell
global g (local s d c) pair     -- local меняет форму дерева: σ(local s d c) ≠ σ(c) = σ(pair)
                                -- zipWith на разных формах не определён
```

Варианты определения: (а) глобальный действует только на дополнение заменённых поддеревьев — тогда это
`zipWith` по *подформе* и нужен проектор «какие узлы свободны»; (б) порядок наоборот: `local s d (global g c pair)` —
сначала шасси идёт к цели на своей фиксированной форме (тотально), затем подставляется цепь, причём калибр `κ`
меряется по **уже смещённому** носителю — и донорская рука дотягивается туда, куда дотягивается рука оборотня.
Вариант (б) тотален и семантически правилен (рука донора встаёт в калибр *того тела, которое видно*). Порядки не
коммутируют: `κ` зависит от длины носителя, а глобальный слой её меняет. **Рекомендую при любом выборе записать в
спеку порядок `local ∘ global` (сначала глобальный)** — сейчас записан обратный, и в коде он ещё не исполнялся,
так что ломать нечего.

**Сложность.** 11 пересекающихся понятий (`04` §1), из них два — мёртвое наследие. Выразительность — образ `eval`
на пространстве 10–40 капсул: это начальная алгебра (свободная генерация из синтаксиса), а не линейная оболочка
авторских точек — диагноз индустрии (`02` §2.3) математически точен. Spore, у которого механизм тот же, записал
ровно наши швы: веса по тому, «какие части тела породили метаболы», и «торс у толстых существ может срезаться» [H].

**Итог В1.** Структура честная (дерево, группа Ли), но два из трёх отображений (`κ` и `eval`) не имеют
универсального свойства, а композиция слоёв в спеке записана в неопределённом порядке.

## 4. В2 — меш на часть + форма-ключ пары

**Структура: алгебра над цветным операдом.** Пусть цвета — типы швов: `Шея`, `Плечо`, `Бедро`, `КореньХвоста`,
`ПоясГруди` (`02` §3.2, `03` П3). Часть вида — операция с одним выходом (шов, которым она крепится) и входами
(швы, которые она несёт): туловище волка — операция `Плечо² × Бедро² × Шея × КореньХвоста → •`, рука —
`∅ → Плечо`. Химера — терм операда: туловище шасси с воткнутыми частями. Склейка по шву — pushout по кольцу
`S_k` (цикл из `k` вершин), и **он тотален, когда цвета совпадают** — стандартное кольцо и есть интерфейс-тип.
Глобальный слой — аффинное пространство `A_c = b_c + span(Δ_{c→t})` на меше(ах) шасси.

**Тотальность.**
- Внутри одного плана тела — тотально по типам: любая `Плечо`-часть в любое `Плечо`-гнездо.
- Межпланная пара (нога стопоходящего двуногого → таз пальцеходящего четвероногого): цвета совпадают по имени
  (`Бедро`), но не по смыслу. Операд это не ловит — анатомически бессмысленная композиция типизируется. Честное
  решение — **разные цвета для разных планов** (`Бедро_двуног ≠ Бедро_четвероног`), и тогда межпланная пересадка
  требует новой операции — «варианта части» (`05` В2 против 2, В5 против 3). Частичность не исчезла, а стала
  видна в типах. Это хорошо: теперь её можно перечислить.
- **Длина части интерфейсом не определена.** Кольцо фиксирует сечение на шве, но не длину конечности. Морфизм
  `S_k → S_k` между кольцами донора и носителя каноничен (Прокруст с известным соответствием вершин — замкнутая
  формула), а масштаб вдоль части — свободный параметр, то есть один из нынешних `κ` выживает. Меньше эвристики,
  но не ноль.

**Корректность по построению.** C⁰-непрерывность шва — да, при равном числе вершин кольца и общей кости-хозяине
кольца. Нормали на шве — нет (`01` §1 F, [29]): это не алгебра, а производная поверхности, её склейка не
выравнивает. Неравномерный масштаб части искажает её — `05` В2 против 3 — ровно потому что морфизм интерфейса
аффинный, а не изометрия.

**Композиция слоёв.** Форма-ключ шасси двигает кольца на его стороне шва; кольцо донорской части стоит на костях.
Если `Δ_{c→t}` на кольце не нулевой (в кадре кости), шов разойдётся. Условие коммутативности —
**граничное условие на форму-ключ: `Δ|_{кольцо} ≡ 0` в кадрах костей** (всё движение кольца объяснено скелетом).
При нём слои коммутируют: глобальный действует на внутренность меша шасси и на скелет, локальный — на части, интерфейс
неподвижен относительно костей. Без него — трещина при каждой ступени. Это требование к контенту, и его можно
проверять машиной (детектор: норма `Δ` на вершинах колец).

**Сложность.** Два механизма (операд + аффинное пространство) — эксперт индустрии считает это достоинством
(`01` §3.4), я соглашаюсь *при* граничном условии выше: тогда механизмы ортогональны (разные носители) и их
сумма проста. Контент: ~35 частей + 20 форм-ключей + варианты межпланных частей.

## 5. В3 — меш шасси + региональные формы-ключи

**Структура.** У каждого шасси — меш `b_c` (n_c вершин) и цели `B_{c,t}` той же топологии, `Δ_{c,t} = B_{c,t} − b_c`
(дельта-формулировка [L] §3.1: `f = b₀ + Bw`). Регионы — **маски-разбиение единицы** `m_r : V → [0,1]`,
`Σ_r m_r(v) = 1`. Веса — **по симплексу на регион**:

```haskell
type W c = Region c -> Simplex (Target c)       -- Π_r Δ^{k}; вершина e_c — «как шасси», e_t — «как цель t»
shape :: W c -> Mesh c
shape w v = b v + Σ_r m_r(v) · Σ_t w(r)(t) · Δ_t(v)      -- аффинно по w, ЛИНЕЙНО по целым целям
```

*(В `05` записано `w : Цель × Регион → [0,1]` без условия суммы — так нельзя: аугмент «ноги → волк» = 1 и
идентичность «всё → лось» = g дают на ногах `Δ_волк + g·Δ_лось` — волчья нога с прибавкой лосиной дельты, форма
вне всякого образа. Это известный в лицевой анимации эффект наложения дельт; [L] §7.3 показывает, что даже два
закрытых глаза в «целых» формах дают не выпуклую комбинацию. Симплекс по региону — правильный тип.)*

**Слои — значения одного типа.**

```haskell
global :: Target c -> Double -> W c -> W c
global t g _ r = (1-g)·e_c + g·e_t                     -- все регионы на отрезке к цели
local  :: Map (Region c) Donor -> W c -> W c
local a w r = maybe (w r) e_ (lookup r a)              -- регион аугмента — в вершину донора
body = shape (local augments (global t g baseline))
```

`local` перекрывает `global` на своих регионах — это приоритет, однозначный по построению; на непересекающихся
регионах слои коммутируют буквально. Противоречия, которое `05` видит в В3 («аугмент — регион носителя, переморфленный
к донору, а потом форма-ключ шасси»), нет: оба — координаты одной точки `W c`, а не два последовательных
преобразования геометрии.

**Тотальность.** `shape` тотальна на всём `W c`; `W c` — компактный многогранник, и вся игра живёт в нём.
Частичность ровно одна: **регион, которого нет в топологии шасси** (хвост у человека, руки у змеи). Это конечное,
перечислимое множество клеток таблицы «шасси × слот»: по разметке графов (`Docs/models/handoff/*-graph.json`)
у змеи нет цепей `перед`/`зад`, у человека — `хвост`; это ~3 клетки из 120. Закрытие — вставкой части по кольцу
(механизм В2, локально) или ригблоком. Вырождать топологию (хвост человека, стянутый в ноль в базовом меше) не
советую: это ровно рудименты Infinigen [I] и вырожденные треугольники В4.

**Что `05` пересчитал неверно — контент.** «140 региональных форм-ключей на вид» не нужны. Регион — это маска, а не
отдельная цель: при разбиении единицы 4 целых цели на шасси дают все 4 × 6 региональных вариантов. Lewis прямо
показывает, что локальный и целый базисы «покрывают одно и то же пространство», переводятся друг в друга
простой алгеброй [L] §7.3–7.4, и что сегментация лица на регионы с независимыми весами гарантирует локальность
[L] §3 (Kleiser 1989). **Контент В3 — 5 мешей + 20 целей**, плюс по нужде «промежуточные» формы для `g₁, g₂`
(их не больше 40, см. ниже).

**Корректность по построению.**
- Топология и связность: одна сетка — шов отсутствует, трещине негде появиться. Сильнейшая гарантия из всех вариантов.
- C⁰ на границе регионов: `shape` — выпуклая комбинация непрерывных полей с непрерывными масками ⇒ непрерывна.
  Гладкость полосы перехода зависит от ширины масок — ручка, а не эвристика.
- **Повороты — не гарантированы, и это главный математический дефект «наивного» В3.** Линейная смесь вершин не
  живёт на SO(3): если цель поворачивает часть на большой угол (пальцехождение, голова «взглядом» — спека §8,
  кадр 01.10), то при `g₁ = 0.4` сегмент укорачивается на хорду — классическое сплющивание линейной интерполяции,
  против которого написана ARAP-интерполяция [A]. Вы это уже знаете: спека 11.09 «тело как расслоение» и §4.3
  спеки двух слоёв смешивают длины в логарифмах и повороты по геодезической. В3 в форме `05` этот урок теряет.
- Самопересечения (рука сквозь туловище при смеси) не гарантированы ни одним линейным методом.

**Лечение поворотов — расслоение (это и есть шестой вариант, §8).** Разложить цель на базу и слой:

```haskell
data Target c = Target { rest :: Skeleton c          -- кадры костей покоя: (ℝ₊)ᵏ × SO(3) на кость — группа Ли
                       , resid :: BoneLocal (Mesh c) } -- дельты вершин в КАДРАХ КОСТЕЙ, остаток формы
mesh w = lbs (geodesic (restWeights w)) (b + Σ_r m_r Σ_t w(r)(t) · resid_t)
```

Большие повороты едет скелет (геодезически — формула спеки §4.3 уже есть), остаток формы мал и линеен. Это
устройство SMPL: форма — блендшейпы в позе покоя, суставы — функция формы, поверх — скиннинг [P]. Поскольку
ступеней всего три (`g ∈ {g₁, g₂, 1}`, плюс 0), промежуточные формы можно доделать руками как «in-between» цели —
стандартный приём блендшейпов [L] §3, — их ≤ 2 × 20 = 40. Непрерывность нужна только на 0.5–1.5 с твина под VFX
(спека §4.5).

**Семантический вопрос «аугмент — не часть донора».** Математически это не потеря, а вопрос авторинга. Если цель
`B_{c,t}` в регионе `r` сделана обтяжкой донорской части на меш шасси (Shrinkwrap/Wrap — `02` §3.1 п. 3, или перенос
деформации [DT]), то вершина `e_t` региона `r` *и есть* донорская часть в калибре шасси — тот же объект, что В2
получает pushout'ом, только без шва. Если же цель — авторский «оборотень» с листа, то `e_t` — «как волчье выглядит на
двуногом». Структура одна, выбор — в данных. GDD §9 («свап = переморфинг, а не перестановка детали») формулирует
ровно второе. Решение за геймдизайнером, но цена решения — ноль строк кода.

**Перенос деформации — подходящий офлайн-инструмент для целей В3, с оговоркой.** Sumner–Popović задают
соответствие как *отношение*, а не функцию: «в большинстве случаев это общее отображение многие-ко-многим»,
и требуют, чтобы общие вершины смежных треугольников переходили в одну точку [DT] §4, ур. (6) — это условие
склейки (как у пучка: локальные данные согласованы на пересечениях). Их же главное ограничение — «требование
грубого сходства» источника и цели [DT] §7. Для пар одного плана (волк↔лось↔ёж) оно выполнено; для межпланных —
нет, и это ещё один довод, что межпланные цели В3 должны быть авторскими, а не перенесёнными.

## 6. В4 и В5

### В4 — единый шаблон (SMAL/SMPL)

**Структура.** Одно аффинное пространство `A = T + span(S_s)` с масками; `Body = A` (не сумма!). Регистрация вида на
шаблон — отображение `species → template`, которое должно быть *функцией на вершинах шаблона*.

**Тотальность куплена вырождением.** Для органов, которых у вида нет, регистрация не инъективна: часть шаблона
стягивается в точку. SMAL признаёт это прямо: ключевая нерешённая задача — «разное число частей (рога, бивни,
хоботы) и части очень разной формы (уши слона)» [S] §9. Частичные функциональные отображения [R] умеют частичность
*соответствия* (ранг-дефицитный оператор между пространствами функций), но не дают *геометрии* недостающей части —
её всё равно нечем рисовать.

**Невостребованная общность.** Главное, что В4 даёт сверх В3, — связность: путь из тела волка в тело змеи внутри
одного пространства. Правила 2 и 8 этот путь запрещают — шасси не меняется, ступень 3 только на родном. Значит, игра
пользуется лишь подмножествами `A_c ⊂ A`, и **В4 с ограничениями игры изоморфен В3 с общим шаблоном**: та же алгебра,
плюс задача регистрации, которая нужна только ради неиспользуемой связности. По Lewis, выпуклые комбинации к тому же
держат форму внутри оболочки точек и не достают до «валидных» форм за её краем [L] §7.5 — при пяти очень разных
видах оболочка широкая, а её середина «ничья».

**Корректность.** Шва нет вовсе (+), суставы по регрессору следуют за формой (+, [P]), но вырожденные треугольники и
промежуточные смеси на границах масок дают тела вне всякого плана (`05` В4 против 1–2).

**Итог.** Самая красивая алгебра, но красота в связности, которую игра не использует. Хорош как *горизонт*, если
однажды появится смена шасси (в бэклоге хвоста-эталона есть «ступень 3 со сменой шасси»). До того — нет.

### В5 — части со стандартным швом и смена модели по ступени

**Структура.** Локально — тот же операд, что В2. Глобально — не операция, а **таблица**: `Map (c, состав, ступень)
Model`. И здесь проблема размерности: состав — функция `Slot → Maybe Donor`, их `5^6` на шасси; «заранее собранные
тела-цели ступени» с аугментами — либо экспоненциальная таблица, либо ступень-модель собирается из частей тем же
операдом. Во втором случае В5 = В2, где вес формы-ключа ограничен множеством `{0, 1}` и заменён скачком. То есть
**В5 — подалгебра В2** (дискретизация глобального слоя), и строго ему уступает: всё, что выражается в В5, выражается
в В2 весами на вершинах; обратное неверно.

**Тотальность** — по типам швов, как В2, с той же межпланной частичностью, которая здесь растёт быстрее (варианты
частей × планы).

## 7. Сложность и контент: конечная таблица

Таблица игры: **5 шасси × ~6 видимых слотов × 4 донора = 120 клеток локального слоя + 20 пар идентичности.**
Это конечный объект. Главный структурный вопрос — сколько **авторских** объектов нужно, чтобы покрыть таблицу без
эвристик, и сколько понятий в коде.

| | авторских объектов | понятий в модели | клеток без эвристики | рост на (n+1)-й вид |
|---|---|---|---|---|
| В1 | 5 графов + 20 парных графов (+ варан) | ~11 (`04` §1) | 0 — все через `κ` | граф + 2n парных |
| В2 | ~35 частей + 20 форм-ключей + межпланные варианты | ~7 (кость, часть, кольцо-цвет, слот, форма-ключ, ригблок, сокет) | все одноплановые; межпланные — по вариантам | ~7 частей + 2n форм-ключей + варианты |
| **В3** | **5 мешей + 20 целей** (+ ≤40 промежуточных) | **~5** (меш, цель, маска, вес-симплекс, ригблок на кости) | 117 из 120; ~3 — вставкой/ригблоком | 1 меш + 2n целей |
| В4 | 1 шаблон + 5 регистраций | ~6, но регистрация — исследование | все, ценой вырождения | 1 регистрация (если влезет в шаблон) |
| В5 | ~35 частей + варианты + 40 моделей ступеней | ~5, но таблица растёт | все одноплановые | части × планы + 2n моделей |

Для **нашей** конечной таблицы минимален В3: наименьшее число понятий, авторских объектов того же порядка, что у
В1, и ноль эвристик на 117 клетках. Квадратичный рост целей (`2n` на новый вид) общий для В1, В2, В3, В5 — он
следует из того, что идентичность — функция пары, а не вида. Линейный рост есть только у В4, и куплен он
вырождением и невостребованной связностью.

## 8. Шестой вариант: В6 = В3 на расслоении + вставка по шву для отсутствующих регионов

Не новый механизм, а сборка из уже обсуждённого так, чтобы закрыть оба дефекта В3 и одну частичность.

```haskell
data Body c = Body
  { weights :: Region c -> Simplex (Target c)          -- оба слоя: аугмент — вершина, идентичность — отрезок
  , inserts :: Map (AbsentRegion c) (Donor, Part)       -- ~3 клетки: часть донора по кольцу (операд В2)
  , blocks  :: Multiset (Bone c, RigBlock)              -- когти, рога, иглы: свободный коммутативный моноид
  }
render (Body w ins bl) =
  lbs (geodesicRest w)                                  -- скелет: (ℝ₊)ᵏ × SO(3), формула спеки §4.3
      (b + Σ_r m_r Σ_t w(r)(t) · resid_t)               -- остаток в кадрах костей, линейно
  ⊔_{кольцо} ins  ⊔  bl                                  -- pushout по стандартным кольцам; детали — на костях
```

Свойства:
- **тотальна** на `W c × (конечное) × (свободный моноид)`; частичность вынесена в тип `AbsentRegion c` и перечислима;
- **слои — координаты одной точки**, порядок задан приоритетом (`local` поверх `global`) и однозначен;
- **повороты на SO(3)**, остаток линеен — урок 11.09 сохранён;
- **шов как тип** только там, где он неизбежен (вставка в отсутствующий регион), с граничным условием `Δ|_{кольцо} = 0`;
- **сохраняется** из нынешнего: дерево (как риг и для геодезической смеси скелета), разметка `limb`/`mark` (она
  задаёт соответствие костей шасси и цели — то самое, что нужно для `geodesicRest`), ригблоки на костях, имя слота =
  имя региона-маски, детекторы. Уходят: поле как рантайм-облик, `κ`-эвристики, гнёзда в долях мест, смешение мест.

Это не противоречит тому, что ресёрч назвал «индустрия решает два слоя двумя механизмами» (`01` §3.4): в В6
механизмов тоже два — веса (оба слоя) и вставка (только частичные клетки), — но второй работает на 3 клетках из 120,
а не на всех.

## 10. Рекомендация и оговорки

1. **Выбрать В3 в форме В6**: тело шасси — один меш на расслоении (скелет в группе Ли + остаток в кадрах костей),
   веса — симплекс на регион, регионы — маски-разбиение единицы, 20 целых целей, аугмент — вершина симплекса,
   идентичность — отрезок, ~3 клетки «нет региона» — вставкой по кольцу или ригблоком.
2. **При любом выборе — поправить спеку двух слоёв §6.1:** глобальный слой ПРЕЖДЕ локального
   (`body = local ∘ global`). Записанный порядок не определён на деревьях разной формы. Если останется В1/В2, это
   решение влияет на калибр: донорская цепь мерится по *уже смещённому* носителю.
3. **При любом выборе — сторож коммутативности локального слоя:** все перестановки слотов дают один отпечаток тела.
   Сегодня это не проверяется, а код применяет замены в порядке таблицы.
4. **Оговорка 1 — красота не следует из алгебры.** В3/В6 выигрывает структурно потому, что выразительность там в
   **базисе** (20 авторских целей), а интерпретатор тривиален. Если цели окажутся «пластилиновыми» (ИИ-меши с
   листа без чистки), алгебра этого не спасёт. Пилот П5 «один оборотень до 7/10» — правильный способ проверить
   именно это до вложений в 20 пар.
5. **Оговорка 2 — линейность только внутри шасси.** В6 не умеет менять шасси. Если геймдизайн когда-нибудь введёт
   «ступень 3 со сменой шасси», это будет **дискретный** переход между слагаемыми суммы `Σ c. Body_c` (под VFX), а не
   путь. Делать его непрерывным — это и есть В4, и тогда к нему стоит вернуться.
6. **Оговорка 3 — частичность не нулевая.** Отсутствующие регионы (~3 клетки) несут шов В2 со всеми его проблемами
   (нормали, масштаб). Это честная цена: её можно перечислить и сторожить, в отличие от `κ`, разлитого по всем 120.
7. **Оговорка 4 — В3 меняет смысл аугмента только если так захотеть.** Цели можно делать обтяжкой донорских частей
   (тогда аугмент = донорская часть без шва) или авторским «оборотнем» (аугмент = переморфинг по GDD §9). Это выбор
   данных, а не структуры.

## В7. Развёртка колец (голос модельной линии, `05-modelnyj.md` §4 «Б») — дополнение

*Дописано по просьбе координатора после основного текста; разделы выше не менялись. Итоговый ранг с учётом В7 — в конце
этого раздела.*

**Суть (по `05-modelnyj.md` §4 Б).** Граф и разметка остаются. Оболочка — не изоповерхность, а кольца сечений вдоль
цепей: между двумя метками ровно `k` колец (число задано разметкой, одно на все виды), в кольце `v = 6–8` вершин.
Развилки (плечо, бедро, шея, корень хвоста) закрываются фиксированными заплатками. Морф — `lerp` вершин; шов
подстановки — сшивка колец одной валентности. Форму строит процедура, без художника.

### Структура

Топологически это **разложение поверхности на штаны**. Кожа зверя — сфера с «дырками» на концах конечностей. Такая
поверхность режется на цилиндры (цепи) и на «штаны» — сферы с тремя дырками (развилки). Если для каждого типа цепи
`k` и `v` фиксированы, а для каждого типа развилки фиксирована комбинаторика заплатки, то у любых двух тел с одним
набором цепей **сетки комбинаторно изоморфны**. Изоморфизм каноничен: кольцо `i` на интервале «метка → метка» и
вершина `j` по углу вокруг оси.

```haskell
type Ring v      = Vec v (ℝ₊ × S¹)                 -- профиль сечения: радиус по направлению, в КАДРЕ сегмента
type Chain k v   = (Skeleton, Vec k (Ring v))      -- база: кости в группе Ли; слой: профили колец
data Body plan   = Body { chains :: Π (c ∈ chainsOf plan). Chain (k c) (v c)
                        , blocks :: Multiset (Bone, RigBlock) }
render :: Body plan -> Mesh plan                    -- топология зависит ТОЛЬКО от plan; заплатки = функции соседних колец
```

Если заплатка развилки — функция соседних колец, у неё нет своих свободных координат. Тогда пространство формы при
фиксированном плане тела — **произведение пространств профилей по цепям, расслоённое над скелетом**.

### Сравнение с В6

Схема та же: расслоение «скелет в группе Ли × линейный слой». Различаются три вещи.

| | В6 | В7 |
|---|---|---|
| откуда слой | авторский меш шасси + авторские цели (остатки в кадрах костей) | профили колец, процедура из графа |
| общая топология | у каждого шасси своя; между видами — только через 20 авторских целей | **у всех видов с одним набором цепей** (волк, лось, ёж; человек без хвоста; змея отдельно) — канонически, по меткам |
| контент пар | 20 целей руками | **0**: парное тело — передискретизация профилей цели по меткам, рост по `O(n)` видов, как у В4 |
| где выразительность | в базисе (авторские точки) | в данных профилей (снимаются сечениями с листа), интерпретатор простой |

**Итого: В7 — это В4, сделанный по цепям, а не по целому телу.** Регистрация на шаблон, главный риск В4, тут
не нужна: координаты на цепи задаются метками и углом, а не оптимизацией. Шаблон один на тип цепи, а не один на
все тела. Это сильный ход.

### Три вопроса координатора

1. **Развилки — не цепи.** Это главное место, где структура держится на договорённости, а не по построению.
   Заплатка — «штаны»; их комбинаторика фиксирована, только если у каждого типа развилки валентности входящих
   колец одинаковы у всех видов (у лопаточного пояса: хребет `v₁`, две руки `v₂`). Сама алгебра этого не требует:
   это контракт данных, и его надо проверять машиной. Геометрию заплатки процедура не гарантирует. Стыки трёх
   цилиндров в Skin-модификаторе и ZSpheres — их известное слабое место, которое там добирают лепкой. Ещё одно
   следствие: внеосевые массы (лопатка, круп, горб, грива) — не цепи. Кольцо в 6–8 вершин даёт горбу одну вершину.
   Либо `v` растёт, либо массы уходят в профиль заплатки, либо остаются буграми. Это потолок формы, не тотальности.
2. **Поза на SO(3).** «Морф — честный `lerp` вершин» из `05-modelnyj.md` повторяет дефект наивного В3 (§5).
   Линейная смесь мировых вершин сплющивает повороты: пальцехождение, голову «взглядом». Но у В7 лечение есть по
   построению. Кольцо естественно хранится в кадре своего сегмента (доля вдоль сегмента + радиальный профиль).
   Тогда морф — геодезия скелета (формула спеки §4.3) × смесь профилей: радиусы в логарифмах, как длины. Поэтому
   **смешивать надо координаты слоя, а не вершины.** Так поворот корректен по построению и даже чище, чем в В6:
   координаты слоя каноничны (радиус, угол), а не авторские остатки.
3. **Тотальность при подстановке цепей разной длины.** Число капсул в цепи здесь не важно: кольца индексируются
   интервалом между метками и долей вдоль него, капсулы — лишь способ записать ось. Поэтому подстановка цепи
   донора — замена блока координат того же типа `Chain k v`: **тотальна** для любых длин и любого числа капсул.
   Сшивка комбинаторно тривиальна (одна валентность), то есть интерфейс-тип есть — как у В2, но даром. Остаются две
   частичности.
   - **Геометрия шва.** Радиус кольца донора ≠ радиус кольца носителя, и длина цепи интерфейсом не задаётся. Сечение
     закрывается канонически: профиль донора нормируется своим корневым кольцом и умножается на корневое кольцо
     носителя — граничное условие на стыке. **Длина остаётся свободным параметром, то есть калибр `κ` по длине
     выживает** (как в В2).
   - **Отсутствующие интервалы и цепи.** Нулевой интервал (лопатка ежа, «обе метки в одной точке») — `k` колец в одной
     точке: вырожденные четырёхугольники, у плоской грани нормаль не определена. Нужно явное правило вырождения.
     Отсутствующая цепь (хвост у человека, конечности у змеи) — те же ~3 клетки, что у В6. При росте из нуля — те же
     рудименты Infinigen [I]. Цель «змея» по-прежнему требует варана: у змеиного графа нет цепей, с которых снимать
     профиль.

**Композиция слоёв.** Глобальный слой — точка на отрезке в произведении слоёв над скелетом (фиксированный план,
форма не меняется). Локальный — замена блока координат. Порядок `local ∘ global` (§3) определён и здесь. Слои
коммутируют на непересекающихся цепях; на заменённой цепи приоритет у локального. Но калибр длины зависит от
смещённого носителя — тот же порядок, что я рекомендую для всех.

### Оценка В7

| критерий | балл | довод |
|---|---|---|
| структурная ясность | 8 | разложение на штаны, цепь = цилиндр, расслоение над скелетом; заплатки — отдельное понятие с контрактом валентностей |
| тотальность | 7 | подстановка тотальна при любой длине и любом числе капсул; вне — отсутствующие цепи, нулевые интервалы, змея через варана |
| композиционность слоёв | 7 | оба слоя на одной фиксированной топологии; `κ` длины делает порядок значимым (`local ∘ global`) |
| корректность по построению | 7 | топология и комбинаторика шва — по построению, поворот — если смешивать слой, а не вершины; геометрия развилок и самопересечения — нет |
| минимальность для таблицы 120+20 | 8 | ~5 понятий; 20 пар считаются, не рисуются; но живы `κ` и правило вырождения |
| расширяемость (сова, лесные виды) | 8 | новый вид = граф + сечения, пары даром (`O(n)`); новый тип цепи (крыло) — новые `k, v`, новый тип развилки — новая заплатка |
| **сумма / 60** | **45** | |

### Обновлённый ранг

**В6 50 > В3 46 > В7 45 > В2 36 = В4 36 > В1 27 = В5 27.**

По структуре В7 почти догоняет В3 и по контенту его обходит (пары даром). Отстаёт в двух местах: калибр длины
выживает, а развилки держатся контрактом. Оговорка 1 из §10 к нему относится сильнее, чем к В6: выразительность у
В7 в процедуре и профилях, без авторского базиса. Его потолок — «чистый лоу-поли из сечений», лист оборотня с
плоскостями морды и рельефом туда может не дотянуть. Алгебра этого не измеряет; измеряет пилот модельной линии —
передняя нога волка (`05-modelnyj.md` §6 п. 3).

**Главное практическое следствие: В7 и В6 не соперники, а одна схема на двух уровнях.** Сетка В7 фиксированной
топологии на шасси — готовый базовый меш В6. Профили вида-цели, передискретизированные на шасси, — готовые цели В6.
Авторские поправки по листу ложатся сверху как остатки в кадрах костей — ровно слой В6. Путь без ломки:
**В7 как процедурное содержимое по умолчанию → В6, когда (и где) пилот покажет, что процедуре не хватает формы.**
Тип тела при этом не меняется — меняется только, откуда берутся точки базиса.
