# Ресёрч: генеративные карты, рельеф, здания и помещения

**Дата:** 2026-10-29. **Статус:** ресёрч, не решение.  
**Зачем:** карта CHIMERA генерируется по сиду; подгонять числа руками — тупик. Нужно понять,
какие математические алгоритмы дают читаемый мир с рельефом, водой, маршрутами, зданием и комнатами,
и что для этого добавить в код.

**Команда:** математик-хаскелист (формализация и гарантии), смотритель леса (аудит текущего конвейера),
арт-директор (читаемость и level design), внешний ресёрч (источники и индустрия).

---

## 0. Вердикт

1. Генератор **детерминирован**, но у него нет **слоя композиции**: 1,5 % площади круче 22°, 0,64 % крон,
   объекты разнесены на 40–1 500 м и не связаны маршрутами. Это не «мало шума», это «нет плана».
2. Главный долг — не алгоритм, а **порядок и происхождение чисел**: станция ищется на сыром поле,
   география строится после, площадка правится логом; крупные формы заданы метрами, а не долями `rin`;
   плотность леса — числом 700, а не кроновым покровом.
3. Для CHIMERA подходит **гибрид C-lite**: авторский скелет из 4–6 якорей → граф мест и связей →
   рельеф под план → constraint-посадка зданий → локальные грамматики/WFC для интерьера и dressing.
   WFC на весь купол, MCTS и CP-SAT в рантайме — «красиво и дорого», без второго носителя.

## 1. Что уже есть и где болит

Фактический конвейер (`DomeWorld.Build`):

```
сид → H0 (fBm+ridged+warp) → гидрология (озеро/река) → вход → место станции (сырое поле)
    → терраса → каньон → овраги → пересчёт platformY → холм → чанки → NavMesh
    → кольцо → вода-меши → устья/гнёзда → ясень → план → комплекс → флора → климат
```

Что уже мешает:

| проблема | факт | чем грозит |
|---|---|---|
| станция ищется до географии | `DomeLabSite.Find` по `SampleHydro`; `platformY` правится после | «станция под землёй» ловится логом, а не инвариантом |
| место — лотерея | 512 хэш-кандидатов, первый годный; fallback не проверен | при смене сида станция переезжает без причины |
| крупные формы в метрах | станция 46×36, холм 38–50, озеро ≤150 | на Ø400 озеро больше чаши, на Ø3000 станция — сарай |
| плотность — число | 700 деревьев, не кроновый покров | 223 дер./км² на Ø2000 и 4 000 на Ø400 |
| NavMesh ≠ граф | `ForestRouteGraph` связен, `Entry → LabDoor` в NavMesh `PathPartial` | «связно» не значит «пройдено» |
| план — три шаблона | `fixed`/`mirror`/`deep-wings`, двери не проверяются геометрически | «генератор комнат» — это сдвиг мебели |
| вход зависит от старого ангара | `EntryPointXZ` берёт угол `HangarSpot` | правка A/C молча переставит вход и весь мир |

Подробный аудит — в отчёте команды; ключевые ссылки: `DomeWorld.cs:196-208`,
`DomeLabSite.cs:94-168`, `DomeHydro.cs:30,79,176-205`, `DomeFlora.cs:312`,

## 2. Математическая постановка

### 2.1 Мир как композиция

```
(s,v) → H0 → W(вода) → E(выемки) → B(флора) → Passability → Site → Plan → V(детектор)
```

- `H0`, `W`, `E` — **чистые композиции** функций;
- `Passability` — **предикат/ограничение**, а не генератор;
- `Site`, `Plan` — **поиск под ограничениями** (argmax по годным);
- `V` — **детектор**, который обязан быть зелёным до записи мира.

### 2.2 Гарантия обязана называть разрешение

Одно поле семплится четырьмя способами:

| потребитель | шаг |
|---|---:|
| меш чанка | `chunkSize / terrainQuads` (5,2 м при Ø2000/48) |
| уклон | центральная разность `e=1 м` |
| `ForestRouteGraph` | `D/128` (15,6 м при Ø2000) |
| NavMesh | воксель 0,35 м |

«Мир проходим» — недопустимая формулировка. Допустимая: «на сетке 128 есть 4-связный путь
с зазором ≥ `r`; на меше уклон p95 ≤ 3°; NavMesh `PathComplete`». Три разных факта, три разных теста.

### 2.3 Детерминизм как сечение

`Gen(s,v) = World`, `Fingerprint(World) = (s,v)`. Нужен **отпечаток мира**:
хэш сетки `SampleGround`, POI, числа чанков/деревьев/логов, шаблона плана. Сейчас его нет.

## 3. Алгоритмы по слоям

### 3.1 Рельеф

| алгоритм | что даёт | цена | гарантии |
|---|---|---|---|
| fBm + ridged + domain warp (есть) | базовая форма | `O(k)` на семпл | ограниченный выход, швы 1:1 |
| **thermal erosion (CA)** | срезает обрывы по talus | `O(N·k)`, локально | **гарантирует уклон ≤ talus** |
| hydraulic droplets (Beyer) | долины, русла, наносы | `O(D·L)`, дорого | эмпирика, не гарантия |
| stream-power PDE | физичные долины, сеть рек | `O(N)` на итерацию, offline | гидрологическая связность |
| FFT-спектр | изотропность, контроль корреляции | `O(N log N)` | не для рантайма |

Вывод: **thermal erosion** — единственный дешёвый способ гарантировать ходимость; гидроэрозию
делать офлайн-прототипом и мерить, а не тащить в сборку.

### 3.2 Вода

- priority-flood + D8 (есть) — базовая вода без внутренних минимумов;
- **D∞/MFD** — мягче русла, без 45°-пилы;
- озеро и река должны выбираться **оценкой** (глубина + длина + близость к POI + площадь),
  а не «максимальная глубина» / «самый длинный трек»;
- радиус озера — от `rin`, не потолок 150 м.

### 3.3 Флора и пятна

| алгоритм | гарантии | вердикт |
|---|---|---|
| dart throwing + grid (есть) | попарное расстояние, но неполнота | оставить, но считать цель, а не 700 |
| **Bridson Poisson-disk** | полный blue-noise, равномерная плотность | для деревьев/камней |
| weighted Voronoi / power diagram | пятна леса и поляны без дыр | для мозаики |
| low-freq fBm threshold | связные пятна без гарантии площади | дешёвый первый шаг |
| WFC | локальная связность, нет глобальных гарантий | только dressing, не карта |

### 3.4 Маршруты и проходимость

- BFS (есть) — «связно в этой сетке», без зазора;
- **distance transform + эрозия свободного** — физический зазор ≥ `r` капсулы;
- Dijkstra/A* с анизотропной ценой — кратчайший путь с учётом уклона/воды/кустов;
- **MST по POI** — связность по построению; +1–2 ребра = петли;
- constrained Delaunay + funnel — точный канал, дороже в поддержке.

Ключ: **связность надо строить, а не проверять**. Сначала POI, потом MST, потом петли,
потом проверка в трёх разрешениях.

### 3.5 Размещение здания

- хэш-rejection (есть) — fallback, не основной;
- **стратифицированная решётка + coarse-to-fine** — ε-полнота: годное место в `a√2/2` от узла;
- оценка — **маржи**, не bool: сухость, уклон, перепад, клиренс до реки/кольца, длина подхода;
- `platformY` — от финального поля, стык «плита ↔ поле» — отдельная маржа.

### 3.6 Комнаты и двери

| алгоритм | гарантии | вердикт |
|---|---|---|
| **BSP / slicing tree** | без наложений, полное покрытие, граф комнат — дерево ⇒ связен | основной для 46×36 |
| shape grammar | гибче, но правила разрастаются | для крыльев/фасадов |
| CP-SAT | полный, но зависимость в Unity | офлайн → ассеты планов |
| WFC | эстетика без гарантий | dressing, не план |
| space syntax | не генератор, а линейка | детектор глубины/интеграции |

Для бункера: BSP + проверка «дверь на общей стене», глубина от лобби, `MD(hall) ≤ 1.2`.
Сейчас валидатор проверяет только наличие записи о двери, а не геометрию.

## 4. Что добавить в CHIMERA

### P0 — видимость решений (1–2 дня)

- `GenTrace`: слой, кандидатов, принято, причины отказов, маржи, время;
- `WorldFingerprint`: хэш мира;
- `SamplingContract`: шаг меша, `e` уклона, `routeRes`, `navVoxel` в одном месте;
- убрать литералы NavMesh 0.35/32 — брать из `DomeGenConfigSO`.

### P1 — честный пол (2–3 дня)

- индекс русла (uniform grid) вместо линейного поиска;
- `ForestRouteGraph` с зазором (distance transform) и компонентами;
- тест `NavMesh ↔ route graph` parity: расхождение — записанный долг, не «баг».

### P2 — станция (3–4 дня)

- `Site.Margins` вместо bool;
- решётка 40→20→10 м, лучший кандидат, fallback только с trace;
- `platformY` от финального поля; стык плиты и поля — маржа.

### P3 — план (2–4 дня)

- валидатор: дверь на общей стене, глубина от лобби, интеграция зала;
- BSP/beam за `labPlanVersion=2`;
- геометрия и мебель — из плана, не из констант.

### P4 — флора (3 дня)

- цель — кроновый покров/плотность, а не 700;
- Poisson/blue-noise + пятна; A/C не трогать без `worldVersion`.

### P5 — эрозия (2–3 дня, offline)

- Python/Anaconda прототип; метрика «до/после»: доля склонов 10–22°, читаемость долин;
- в рантайм — только thermal erosion, если метрика оправдает.

### P6 — дороги (2–3 дня)

- POI → MST → 1–2 петли; после B1, когда POI стабильны.

## 5. Три архитектуры

| | контроль | новизна | цена | риск |
|---|---:|---:|---:|---:|
| **A. Правила + поиск** | высокий | низкая | низкая | низкий |
| **B. WFC/грамматика** | средний | высокая | средняя | высокий (шум, dead-end) |
| **C. Гибрид** | высокий | высокая | высокая | средний (сложность) |

**Рекомендация:** C-lite — авторский скелет + граф мест/связей + constraint-посадка +
локальная грамматика бункера. WFC — только dressing. Это использует уже существующие
s11-записи и `LabPlan`, не требует переписывать `SampleGround`.

## 6. Что мерить

| метрика | чем | ворота? |
|---|---|---|
| связность `Entry → LabDoor → LabAtrium` | route graph + NavMesh | да |
| зазор маршрута ≥ капсулы | distance transform | да |
| уклон на меше p95 | треугольники vs поле | да |
| посадка станции | маржи, `platformY`, стык | да |
| план | дверь на стене, глубина, `MD(hall)` | да |
| петли | `μ=E−V+C`, detour, экономия | да для «петли» |
| плотность/крона | NN, покров, пятна | оценка |
| 20 сидов | распределения, p10/худший | да |
| отпечаток мира | hash | да |

**Не путать:** `ForestRouteGraph` — дешёвый детектор по одному полу; NavMesh — отдельный факт.
Сейчас граф связывает 20 сидов, а NavMesh `Entry → LabDoor` — `PathPartial`.

## 8. Развилки для геймдизайнера

1. **2 км — место, которое учат, или декорация на один забег?** От этого зависит, нужен ли
   авторский скелет или полная процедура.
2. **Вода и деревья — механика или картинка?** Сейчас вода проходится по дну, деревья не режут LOS;
   без решения никакая грамматика не сделает их укрытием/границей.
3. **Станция — закрытая точка или проходной двор?** Северная дверь даёт дешёвую петлю, но меняет
   формулировку «станция закрыта».

## 9. Чего не делать

- не переписывать `SampleGround` и `DomeWorld.Build` — это рабочее тело A/C;
- не тащить WFC на весь купол: нет глобальных гарантий, нет второго носителя;
- не запускать гидроэрозию в рантайме до замера: 556k капель — это минуты, не 4.5 с;
- не делать MCTS/CP-SAT в рантайме без второго носителя;
- не вводить числа без происхождения — даже «очевидно правильные»;
- не менять A/C без `worldVersion` и нового профиля.
