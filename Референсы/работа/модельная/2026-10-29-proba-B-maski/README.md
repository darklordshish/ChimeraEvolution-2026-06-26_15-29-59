# Проба Б — поза ступени по маскам листа (29.10)

Задача (ГеймБосс, одобрено геймдизайнером): расхождение с листом сидит в 3D-цели Hunyuan (ноги параллельны, стопа длинная), поэтому
шаг, разнос коленей и стопу ставит только функционал против МАСОК ЛИСТА. Доводка поверх подгонки r5, не замена. Схема — по SMAL
(Zuffi и др., «3D Menagerie»; Animal3D): силуэты по ракурсам, ключевые точки, регуляризатор, параметры — поза.

## Метод (`Tools/Blender/proba/poza_po_maskam.py`, numpy + scipy + PIL; тело — `telo_npz.py`)

- **Параметры — поза, не вершины:** повороты вокруг оси X мира через сустав у стоп (наклон), плеч, предплечий, хребта, шеи, головы;
  ноги — **обратной кинематикой**: у каждой ноги сдвиг скакательного по глубине и высоте (см), бедро и голень — двухзвенным решением,
  стопа держит ориентацию. Поворот одного бедра отрывал стопу от земли, штраф его гасил — ноги не двигались. Форма тела, куски,
  швы и веса не трогаются.
- **Функционал:** Σ по ракурсам (анфас 1, профиль 1, сзади 0.5) (1 − IoU) с масками ортопары r2 — IoU как у стенда (орто-проекция,
  рамка по фигуре, `norm512`); + удержание у позы r5 λ Σ (δ/10)²; + разность высот стоп; + **развороты граней** ν·N — мера стенда
  (нормаль грани тела в позе против нормали базового тела, повёрнутой главной костью), совпадает со стендом до единицы.
- **Минимум:** метод Пауэлла (без градиента; силуэт кусочно-постоянен), 3 прохода, ~335 оценок по 0.7 с — **3.7 мин**.
- Ключевые точки суставов не понадобились: уровни профиля уже совпадали с горизонталями листа в пределах 2 % (критик).

Поза Б (`poza-po-maskam.json`): скакательные — правый +2.6 см назад, левый −3.6 см вперёд (поверх шага r5; по глубине они теперь в
30 см друг от друга, колени — в 19 см); шея −9.5°, голова +8.5°, предплечья +2.9° / −5.8°, плечо −2.4°. Стопы на земле обе.

«Окна» стенда — просветы позы, а не дыры сетки: +4 — это профиль между ногами (25×22 см на высоте 0.24 м — треугольник листа, который
просил критик) и между рукой и телом; изнанки нет вовсе.

Кадры: `b5_*.png` — поза Б, `r5_*.png` — r5.

## Чего Б не делает

- **Стопа-ласт остаётся:** длина стопы — форма цели, поза её не укорачивает; наклон стопы оптимизатор не тронул (круче — пальцы в
  землю, профиль хуже). Стопу ставит только форма: цель или ключ (см. r4 — укороченная стопа цели роняла профиль, потому что ноги
  уходили под таз; с позой по маскам эту пробу стоит повторить — оптимизатор сам вынесет ногу вперёд).
- Разнос коленей вырос умеренно (16 → 19 см): дальше его держит штраф разворотов и вид анфаса.

## Вывод

Проба Б заменяет ручной подбор позы ступени (`poza_shag.py` ±12 см, руки −12°/+8° — и прежние десятки проб поворотов): одна команда,
3.7 мин, лучше r5 во всех трёх ракурсах и по разворотам граней. Встраивается в сборку последним шагом (после выгрузки тела ступени):
меняется только файл позы ступени — швы, куски, веса и ключи не трогаются. Следующий шаг по этой линии — та же схема с параметрами
формы стопы (ключ ниже скакательного), чтобы снять ласт.
